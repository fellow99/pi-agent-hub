## 1. 系统目的与目标用户

多智能体会话的**汇总、只读查看与受控下发/导入**服务：

- 每台运行 agent（pi / opencode / dsh 等）的机器上常驻一个 daemon，读取本机会话存档并持续上行汇总；
- hub 以统一结构（pi 会话格式）落盘镜像，提供只读清单/正文/搜索；
- 需要向某会话发消息时，经 hub 下行推送到目标机器 daemon，再由 agent 自身接口执行。

目标用户：多智能体开发者/团队（自托管、单管理员 + 若干 viewer）。

## 2. 核心能力（用户故事形式）

### 2.1 会话汇总（上行，已实现骨架）
- 作为 daemon，我可以枚举本机 agent 的会话清单并上报，以便 hub 知道有哪些会话。
- 作为 daemon，我可以按「上次同步位点」增量读取会话正文并上传，以便 hub 镜像保持最新。
- 作为 hub，我可以依据（主机、agent、本地会话 id）稳定识别同一会话，且不同主机的同名会话互不冲突。

### 2.2 只读会话查看（已实现最小版）
- 作为登录用户，我可以查看会话列表（主机/agent/项目/标题/条目数/最后更新）。
- 作为登录用户，我可以查看某个会话的正文（按时间排序的条目块、文本/思考/工具调用等类型）。
- 作为登录用户，我可以按关键词搜索会话（当前仅标题/path 匹配，TODO 全文搜索）。
- 系统必须保证查看路径是只读的：不修改任何会话内容。

### 2.3 对话下发（下行，已实现骨架）
- 作为 admin，我可以选择某个会话发送一条消息。
- 系统应把该消息下发到对应的机器 daemon，再由 agent 自身接口把消息送进会话。
- 系统应跟踪下发状态（queued/dispatched/accepted/completed/failed）。

### 2.4 会话导入 / 原生快照（TODO/骨架）
- 作为 admin，我可以把 hub 中的某会话在目标机器上新建为原生会话（当前 `/api/hub/imports` 未接线，返回 501）。
- 同源（同 kind）导入可使用原生快照 `export_native`（插件已实现导出，链路未完整接通）。

### 2.5 主机与身份（已实现）
- 系统以「预配置 token」识别每台主机；以「用户名+密码」识别查看用户；角色仅 admin / viewer。
- 作为 viewer，我只有只读权限；写操作（下发/导入/重置/配置）需 admin。

## 5. 系统边界

**范围内**
- 会话汇总（上行）、只读查看（列表/正文/搜索）、下发（下行）、导入（骨架）、主机/身份、控制 API、Docker 部署、托盘守护。

**范围外（本期不做）**
- 导出/分享链接、多租户 RBAC、端到端加密、hub→agent 持续双向同步、模型/推理托管、pi-web 集成。
- 上行大文件 upload 流、断线事件重放、脱敏、FTS5 全文搜索（均列为 TODO，尚未完成）。

## 6. 验收要点（当前可验证）

- manifest 新会话返回 `lastTimestamp:null`，完整同步后可读回正文。
- 重复同步同一批 entry 不产生重复条目（幂等）。
- 查看 API 无写方法（GET only）；console 无编辑入口。
- daemon 与 hub 通过配置 token 建立信任；未知 token 返回 401。
