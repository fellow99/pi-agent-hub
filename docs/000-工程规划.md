# pi-agent-hub — 工程规划

> **一句话**：`pi-agent-hub` 是一个**多智能体会话汇总、查看与下发服务**。每台运行 agent 的机器上装一个
> `sync-daemon`：它读取本机各 agent 的 **session 存档**，把异构格式统一成同一套数据结构后用 **REST**
> 同步到 `hub-service`；hub 按 **pi 会话结构**落盘。查看与操作统一由 **hub-console** 提供 ——
> **不引入 pi-web**，会话列表、正文、搜索全部由 console 直接渲染。
> 需要向某个会话发消息时，console 选择「机器 + agent + session」，hub 通过 **SSE** 把消息推给该机器的
> `sync-daemon`，daemon 再调用该 agent 的 **ACL/ACP 或原生 API** 把消息送进会话。

| 项 | 值 |
|---|---|
| 工程 | `pi-agent-hub`（`pi-workspace` 的子模块） |
| 模块 | `hub-service`（服务）· `hub-console`（会话查看 + 控制台）· `sync-daemon`（采集/执行） |
| 形态 | 中心化服务（Linux / Docker）+ 每主机常驻守护进程 |
| 本期适配 | **pi**、**opencode**、**deepseek-harness**（下称 `dsh`） |
| 后续适配 | claude code、codex 等（经 ACP 或原生 API，本期只留适配器契约） |
| 存储格式 | **pi session format v3**（JSONL + 目录布局与 pi `agentDir/sessions` 一致） |
| UI | **hub-console 自研**（只读会话视图 + 控制面）；**不使用 pi-web** |
| 同步方向 | agent → daemon → hub（上行 REST）；hub → daemon（SSE 下行） |
| 上游基线 | `pi` **v1.2.0**（与父工程 `specs/README.md` 同日基线） |
| 文档版本 | **v0.13**（2026-11-09，规划草案，待评审） |
| 读取实现 | hub-service 使用 `@earendil-works/pi-coding-agent` 的**只读 API**（pi 内核，版本锁定） |
| 技术栈 | **Node 24 + Express 5 + pi SDK**（hub）· **Vite + Vue 3 + Element Plus**（console）· **Node 24**（daemon/插件）· **Tauri v2 + HTML**（托盘，仅 Win/macOS） |
| 当前状态 | **脚手架已落地**：pnpm workspace + packages（hub-service / hub-console / sync-daemon / sync-plugin-* / sync-daemon-tray）；功能待逐项实现与 E2E |

### 0.3 非目标

- **不引入 pi-web**（也不 fork/嵌 iframe）：会话查看由 hub-console 自行实现。
- **不 fork 上游**：`pi` 只作为**存储格式参考与只读解析库**使用；不改一行。
- **不替代各 agent 的原生 UI**：hub 只做汇总、查看、下发、导入。
- **不做 hub→agent 的持续双向同步**：上行是持续汇总；下行只有「一条消息」与「一次性导入」。
- **不做模型/推理托管**：不代理 LLM 请求，不保存 API Key。
- **不做多租户 SaaS**（本期）：单团队、单管理员 + 机器令牌。
- **不做端到端加密**（本期）：TLS + 令牌 + 可选静态加密。
- **不做跨 agent 的 100% 无损导入**：同 agent 优先无损，跨 agent 显式标记有损。

### 0.4 术语

| 术语 | 含义 |
|---|---|
| **agent** | 异构智能体产品：`pi` / `opencode` / `dsh` / claude / codex … |
| **agent instance** | 主机上的一个 agent 安装实例（同一主机可多份，如不同 `PI_CODING_AGENT_DIR`） |
| **session archive** | agent 自己的会话存档（pi 的 JSONL、opencode 的 SQLite、dsh 的 JSONL.zstd …） |
| **agent 控制接口（ACL / ACP / 原生 API）** | 触发某会话聊天、创建/导入会话的接口：下发优先 **ACP**，否则原生 API（pi RPC、opencode HTTP、dsh `/api`）；读取优先级见 Q9 |
| **manifest** | daemon 上报的「本机所有 session ID + 本地更新时间」清单 |
| **lastTimestamp** | hub 侧某 session 已存的最后一条 entry 时间戳；`null` 表示需要完整同步 |
| **canonical entries** | 归一后的中间表示，**就是 pi session entries** |
| **hub session** | hub 存储中的会话：一个 pi 格式 `.jsonl`，文件名 `<ts>_<hubSessionId>.jsonl` |
| **merge** | hub 收到一批 entries 后按 id/时间戳去重、追加或整会话替换 |
| **transcript** | hub-service 把 entries 规范化后的「会话正文块」，供 hub-console 渲染 |
| **deliver** | 向某 agent 的某 native session 发一条聊天消息并触发执行 |
| **import** | 把 hub 的某个 session 在目标 agent 上**新建**为原生会话（一次性） |

## 1. 项目概述

### 1.1 模块分工

| 模块 | 归属 | 负责 | 不负责 |
|---|---|---|---|
| **各 agent**（pi/opencode/dsh/claude/codex…） | 上游/外部 | ① 可读取自己的 **session 存档**；② 提供 **ACL/ACP 或原生 API** 触发某会话聊天、创建/导入会话 | 不感知 hub |
| **sync-daemon** | 本工程 | ① 管理本机 agent 实例与插件进程；② 汇总清单、时间戳差分、REST 同步；③ 保持 SSE；④ 把 `deliver`/`import` 交给插件执行；⑤ 脱敏与 spool | 不做存储权威、不做 UI、不做模型调用 |
| **sync-plugin-*** | 本工程 | 每个 agent 一个**独立 Node 子进程**（npm 包）：读存档→canonical entries、调用 agent 的 ACL/ACP/API 下发、导入 | 不直连 hub；不写 hub 存储 |
| **sync-daemon-tray**（Win/macOS） | 本工程 | **Tauri** 托盘/菜单栏程序：守护 daemon、配置界面、状态/暂停/恢复/打开 console/日志 | 不做采集/同步业务 |
| **hub-service** | 本工程 | ① 与 daemon 对接（REST 同步 + SSE 下行）；② **合并**进 pi 存储结构；③ 提供会话读取 API（列表/正文/搜索）；④ 提供控制面 API；⑤ 托管 console 静态资源 | 不直接读 agent 存档、不直接连 agent、不渲染 UI |
| **hub-console** | 本工程 | ① **会话查看**（列表、正文、搜索，只读）；② 控制面（主机/agent/下发/导入/审计/设置） | 不写入会话内容；不直连 daemon/agent |
| **pi-web** | **不参与本工程** | — | — （父工程其他子工程仍可能使用，与本工程无关） |

**职责边界一句话**：**agent 提供存档与执行接口；daemon 负责归一与执行；hub-service 负责存储、协议与读取 API；
console 负责查看与操作。**

### 1.2 三条业务流程

**① session 汇总（上行，持续）**

```text
sync-daemon
  ① 采集本机各异构 agent 的所有 session ID
  ② 提交到 hub（manifest）
  ③ hub 返回这些 session 在 hub 的最后时间戳（null = 需要完整同步）
  ④ daemon 按时间戳提取要同步的上下文
  ⑤ 同步到 hub
  ⑥ hub 合并 session 上下文内容
```

**② session 对话下发（下行，SSE）**

```text
hub-console
  ① 选择「指定机器 + 指定 agent + 指定 session」
  ② 发送一条消息
  ③ hub 通过 SSE 推送到该机器的 sync-daemon
  ④ daemon 调用对应 agent 的 ACL/ACP 或 API，把消息发到该 session
```

**③ session 导入（附加，一次性）**

```text
hub-console → hub-service → SSE import → daemon 调 agent 创建接口 → 目标机新建会话
```

### 1.5 上游身份与许可

`pi`（MIT，`earendil-works/pi`）、`opencode`、`dsh` 均为上游开源项目。本工程不隶属、不背书，只做外部集成。
`pi` 在本工程中只作为**存储格式参考与只读解析 SDK**使用；`pi-web` 不参与运行时。
分发时随包给出所用上游的第三方许可清单（§12.4）。

### 2.2 非功能需求（NFR）

| 编号 | 需求 | 目标值（可测） |
|---|---|---|
| **NFR-1** | 规模 | 单 hub **≥ 50 主机 / 500 agent 实例 / 50k 会话 / 20M 条目** |
| **NFR-2** | 汇总延迟 | 本机/局域网新条目 **< 5 s** 到 hub；公网 **< 15 s**（P95） |

| **NFR-6** | 只读查看 | 查看路径**不写**任何 native 存档；会话内容 API 只有 GET；console 无编辑入口 |
| **NFR-7** | 可恢复 | SQLite 索引可从 JSONL 全量重建；单会话可要求完整重同步 |
| **NFR-8** | 安全 | 全链路 TLS；令牌可吊销；命令仅 `deliver`/`import`；不以 root 运行 |
| **NFR-9** | 可移植 | hub 跑 Linux（Docker 优先）；daemon 支持 **Windows / macOS / Linux** |
| **NFR-10** | 可观测 | 结构化日志 + 指标（水位、延迟、失败率、SSE 连接数）+ 审计表 |
| **NFR-11** | 查看性能 | 1 万条 entry 的会话：首屏（100 条）**< 1.5 s**；滚动 60 fps；搜索 P95 **< 500 ms**（50k 会话） |
| **NFR-12** | 渲染安全 | Markdown 禁 raw HTML；CSP；工具输出按纯文本渲染；链接协议白名单 |
| **NFR-13** | 端侧资源 | 空闲 daemon RSS **< 120 MB**；单插件空闲 **< 200 MB**（⬜ 实测）；插件崩溃不影响 daemon |
| **NFR-14** | 端侧形态 | Win/macOS：**用户级 daemon，由 Tauri 托盘守护**；Linux：**node + pm2 + daemon**；均不以 root 运行 |

### 2.3 硬约束（C）

| 编号 | 约束 | 影响 |
|---|---|---|
| **C-1** | pi 会话文件是**单写者**语义（无文件锁） | ⚠️ 下发前必须做空闲/冲突检查（§10.2） |
| **C-2** | 各 agent 存档格式/时间戳精度不一致 | ⚠️ 用 `(timestamp, entryId)` 双游标，必要时整会话重发（§7.4） |
| **C-3** | opencode SQLite schema 随版本演进（V1/V2） | 插件需版本识别/兼容；不可读回退 API（§8.2） |
| **C-4** | dsh 默认 zstd 帧 +「一个 root 一种编码」 | 优先直读（zstd 解码）；不可读回退 host API（§8.3） |
| **C-5** | 各 agent 的 provider/model 元数据不可互通 | ⚠️ 跨 agent 导入必须标「有损」 |
| **C-6** | 会话可能含密钥/内网地址/源码 | ⚠️ 脱敏与访问控制是 P1 硬需求 |
| **C-7** | 正文可能包含超大工具输出/图片（base64） | ⚠️ 必须分页/截断/按需加载（§6.4） |
| **C-8** | hub 单实例：SSE 连接表 + SQLite 单写者 | ✅ 已确认只做单实例；多副本不在本期 |
| **C-9** | Node 插件与 daemon 同进程会互相拖垮 | ⚠️ 插件必须**子进程 + JSON-RPC**，不在 daemon 内 `import()` 执行（§7.11） |
| **C-10** | Win/macOS 用户级：托盘退出/崩溃时 daemon 的生命周期需明确 | ⚠️ 默认「托盘守护 daemon，退出托盘即停」；headless 用 npm/pm2（§7.10） |
| **C-11** | Express/反代默认会缓冲 SSE | ⚠️ 必须关闭缓冲/压缩并调大读超时（§13.1） |

| 候选 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. REST 上行 + SSE 下行** | daemon 用 REST 推同步；用 SSE 长连接接下发 | 上行简单可重试；下行实时且只需单向；代理友好；无需 WS | SSE 需心跳/补发；反代需关缓冲 | ✅ **采纳** |
| B. WSS 双向帧 | 一条 WebSocket 双向 | 延迟低 | 代理/粘性会话复杂；状态与背压自研；**用户明确不用** | ❌ |
| C. 长轮询下行 | `GET /commands?wait=25` | 无长连接 | 需命令队列 + 租约；实现更重 | ❌（改用 SSE） |
| D. hub 拉 daemon / Webhook | hub 主动连 daemon | — | 需入站端口；NAT 不可行 | ❌ |

### 3.3 D-2 同步协议：manifest → 时间戳差分 → merge ✅ 采纳

| 候选 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. manifest + 时间戳差分** | daemon 报 session 清单与本地更新时间；hub 返回最后时间戳；daemon 只发之后的条目 | 传输最小；天然支持「空时间戳 = 全量」；直白 | 时间戳碰撞需 tie-breaker；源改历史需 full | ✅ **采纳** |
| B. 纯字节游标 | 按文件 offset 增量 | 传输最省 | 异构存档不统一；重写检测复杂 | ❌（仅 pi 适配器内部优化） |
| C. 全量覆盖 | 每次发整会话 | 简单 | 带宽/延迟不可接受 | ❌ |
| D. 事件序号 | 每存档维护单调 seq | 精确 | 各 agent 无统一序号；需侵入改造 | ❌ |

补充：契约以**时间戳**为主（按需求原文），`lastEntryId` 仅作同毫秒 tie-breaker；
无法提供稳定顺序的适配器，对该会话回退 `mode=full`。

### 3.4 D-3 统一存储：单棵 pi 结构 ✅ 采纳（**已确认**）

| 候选 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 单棵 pi 结构** | `~/.pi-agent-hub/agent/sessions/<provenance-dir>/<ts>_<id>.jsonl` | 格式稳定、工具可读、可用 pi SDK 解析；单库单目录 | 需保证 JSONL 合法；占用磁盘 | ✅ **采纳** |
| B. 自有 JSON 表 | 直接存 SQLite/自定义格式 | 查询灵活 | 丢失 pi 生态兼容；正文与索引耦合 | ❌ |
| C. 每（主机,agent）一棵 | 分目录隔离 | 清晰 | 跨源检索/统计复杂 | 🔶 规模退路 |

> 说明：去掉 pi-web **不等于**放弃 pi 存储格式。格式保留的理由：稳定、可被 pi/pi SDK 读取、
> 便于未来迁移或与 pi 工具互通；但 hub 不再依赖 pi-web 的 UI 或 `/api/*`。
>
> **评审确认（2026-11-09）**：保留 pi v3 格式；hub-service 直接使用 pi 内核（pi SDK）读取。

### 3.5 D-4 归一化：daemon 侧归一 + hub 校验 ✅ 采纳

| 候选 | 结论 | 理由 |
|---|---|---|
| **daemon 归一** | ✅ | hub 简单；上传量小；脱敏在源头；适配器独立演进 |
| hub 归一 | ❌ | hub 要懂 N 种格式与版本；原始包大；脱敏滞后 |
| 双写（canonical + 原生快照） | 🔶 | 仅导入/取证时按需上传原生快照 |

### 3.6 D-5 会话查看：hub-console 自研（替代 pi-web）✅ 采纳

| 候选 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. hub-console 自研** | service 提供 transcript API；console 用 Vue 3 渲染 | 完全可控；与下发/导入同界面；无额外进程；无只读网关 | 需自研渲染/搜索；要覆盖工具输出、图片、diff | ✅ **采纳** |
| B. 引入 pi-web + 反代白名单 | 原方案 | 零渲染开发 | 多一个 Next 进程；只读网关/白名单维护；已决定去掉 | ❌ |
| C. iframe 嵌 pi-web | 嵌到 console | 复用 | 两套 UI/登录；写入风险；已决定去掉 | ❌ |
| D. 只提供 CLI/API | 无 UI | 最省 | 不满足「查看」需求 | ❌ |

**结论**：去掉 pi-web；hub-service 提供**只读会话读取 API + transcript 规范化**，hub-console 负责渲染。

### 3.14 开放问题头脑风暴（2026-11-09）

> 下列为**最终决定与取舍**（已确认，见 §3.13）。评估维度：安全、运维成本、实现成本、可回退。

#### Q1 多用户 / 认证（不做 RBAC）

**最终决定：不做 RBAC，只做 `admin` / `viewer` 两种角色；用户、密码、角色、daemon token 全部写在 hub-service 配置中。**

- 配置文件：`~/.pi-agent-hub/hub-service.json`，同时支持 `hub-service.yml`（同结构）；
- `users[]`：`username` + `password`（开发期明文）或 `passwordHash`（Argon2id）+ `role: admin|viewer`；
- `daemonTokens[]`：`name` + `token`（或 `tokenHash`）+ `hostName` + 可选 `labels`；每个 daemon 用不同 token；
- `admin`：全功能（下发/导入/resync/pin/配置/审计/force）；
- `viewer`：**只读**所有 host / agent / session / transcript / search；不能下发、导入、resync、pin、看审计、改配置；
- 无用户管理 UI；改配置后重启或 `POST /api/hub/reload`（admin）；
- 密码推荐 Argon2id；明文仅开发期且文件 `0600`；
- token 轮换：改配置 + 重启/reload；未知/禁用 token → `401`；
- 不做：RBAC、SSO、按主机 ACL、用户 CRUD UI、导出/分享（见 Q8）。

数据模型：`users(username, password_hash, role, disabled)`；`daemon_tokens(name, token_hash, host_id, labels)`；审计记录 `actor_username`。

#### Q2 无人值守下发策略

| 候选 | 说明 | 评价 |
|---|---|---|
| A. 一律禁止 | 必须有人在目标机确认 | 废掉远程下发价值 |
| **B. 分层策略** | 桌面 `idle-only`；常驻 `managed-only`；`force` 仅 admin | ✅ 推荐 |
| C. 审批工作流 | 提交→审批→执行 | 成本高，Phase 3 |
| D. 全放开 | 任何会话随时下发 | 并发写/成本风险 |

**最终 B**：

- 每 host/agent 配 `deliver: off | idle-only | managed-only`；
- 桌面默认 `idle-only`（近 120 s 无写入、无运行中 agent）；
- 常驻/服务器默认 `managed-only`（仅 hub 导入/登记的会话）；
- `force` 仅 `admin` + 二次确认 + 审计；`viewer` 不可下发；
- 加每日运行次数/成本上限、并发上限、托盘与 console 的「一键暂停」；
- 冲突不重试，失败可见。
- 不做：多级审批（Phase 3）、按模型/时段白名单（后续可加）。

#### Q4 镜像保留期

**最终决定：30 天默认；host/agent 可覆盖 7/30/90；pin 豁免。**

- 每日 GC；删除前仅告警，**不提供导出**（Q8）；
- `retentionDays=0` 禁止（防误设永久）；
- 源存档仍在 agent 侧，hub 镜像可重建；
- 冷归档（S3/兼容存储）Phase 3。

#### Q5 原生快照

**最终决定：hub 只存 canonical；同 kind 导入时按需 `export_native`，点对点中转，用后删除。**

- 新增 SSE 命令 `export_native`：hub 向**源 daemon**请求原生快照；
- 源 daemon 调插件 `export_native` 生成原生文件 → 上传到 hub 临时存储（TTL 1 h，加密在途）；
- hub 把临时引用放进 import bundle → **目标 daemon** 下载 → 导入后 hub 删除；
- hub 只保留 `sha256/size/createdAt` 元数据，不长期保存原文；
- 跨 agent 不使用原生快照（用 canonical）；
- ⚠️ 原生快照可能绕过 canonical 脱敏：仅同 kind、仅 admin 可发起、审计、TTL、目标限定；
- 取证模式（可选）：TTL 7 天 + 加密，默认关闭。

#### Q6 跨 agent 导入

**最终决定：端侧插件负责异构适配与归一；hub-service 以 pi 为内核；跨 agent 导入由目标插件的 `import` 能力决定。**

- 同 kind：无损优先（pi 复制 entries；opencode `export/import`）；
- 跨 kind：目标插件若能消费 canonical / 原生 bundle，就允许；**MVP 验证目标 pi**；
- opencode 目标按 API 稳定度后续；dsh 目标本期 `unsupported`；
- 显式标记 lossy（provider/model/thinking/branch）；
- 不在 hub 里写 N×N 转换矩阵；转换逻辑属于插件。

#### Q7 console 多语言

**最终决定：zh-CN + en；`vue-i18n`；默认跟随浏览器。**

- 用户可在设置里切换；服务端错误码 → 前端映射；
- CI 校验 key 对齐；日志/审计原文不翻译；
- 后续加语言只增加 locale 文件；不做服务端 i18n。

#### Q8 导出与分享

**最终决定：不做导出、不做分享链接。**

- console 只提供只读查看（列表/正文/搜索）；没有 Markdown/JSONL 下载，没有 `/share` 链接；
- 需要留存时由 admin 在**服务器文件系统**侧处理（不属于产品功能）；
- 这同时消除了匿名链接、导出文件泄露和下载接口的 XSS/越权面；
- 未来若恢复，必须是短期签名、单会话、只读、可撤销、审计（不在本期）。

#### Q9 读取与下发的接口优先级

**最终决定（两条不同的优先级）：**

| 方向 | 优先级 |
|---|---|
| **session 同步（读）** | ① **直读 agent 存储格式**（版本适配，如 opencode V1/V2）→ ② agent API → ③ ACP |
| **消息下发（写）** | ① **ACP** → ② agent API |

说明：

- 直读存储是首选：最快、最完整、不依赖 agent 进程；插件必须做**存储版本识别与兼容**；
- 存储不可读/版本不支持 → 回退 API；API 也不可用 → 回退 ACP；
- 下发优先 ACP（统一、面向会话）；没有 ACP 时用原生 API；
- 插件内部实现优先级与降级；daemon/hub 不感知具体协议；
- 能力声明：`controlInterface`、`readStrategy`、`deliveryStrategy`（可选）供 console 展示。

### 4.2 进程与模块

| 进程 | 归属 | 职责 | 生命周期 |
|---|---|---|---|
| `hub-service` | 本工程 | edge + 同步 + 镜像 + transcript + 搜索 + SSE + 调度 + 静态托管 | 常驻（systemd/容器） |

### 4.4 流程②：对话下发（SSE）

```text
hub-console        hub-service                 daemon                agent
    │                   │                        │                     │
    │ POST /api/hub/    │                        │                     │
    │ deliveries ──────►│ 校验目标在线/会话存在     │                     │
    │                   │ 幂等键 + 每会话串行        │                     │
    │                   │ 分配 eventId 入缓冲       │                     │
    │                   │ ── SSE event: deliver ─►│                     │
    │                   │   id: <eventId>         │ 幂等检查(deliveryId) │

    │                   │                        │ ◄── 接受/开始 ──────│

```

关键点：
- **SSE 只负责推送**，执行结果走 REST 回执；
- 断线重连带 `Last-Event-ID`，hub 从每主机缓冲重放；缓冲过期则用 REST pending 补齐；
- 每条事件有全局 `eventId`；`deliveryId` 是业务幂等键。

### 4.5 流程③：会话导入

```text
console → hub: POST /api/hub/imports {hubSessionId, targetHost, targetAgent, targetCwd?}
  → hub 生成 bundle（canonical entries + 可选 native 快照），分配 importId
  → SSE event: import {importId, bundleUrl, targetAgentId, targetCwd}
  → daemon: GET bundle（Range 分块）→ 调 agent 导入能力：
        pi:       写新 JSONL（新 id）或 CLI 会话导入
        opencode: session.import
        dsh:      本期 unsupported（⬜）
  → daemon: POST /api/v1/imports/{id}/result {nativeId, nativePath, warnings}
  → hub: 记录 provenance；新会话随后经流程①出现在 hub
```

### 4.6 失败与降级

| 失败点 | 行为 |
|---|---|
| daemon 离线 | 汇总暂停（水位保留）；下发/导入在 hub 排队（默认 TTL 24 h） |
| SSE 断开 | 重连 + `Last-Event-ID`；不可恢复时 REST 补齐 pending |
| console 静态资源 404 | edge 返回 404 + 版本信息；不影响 API |
| 单会话解析失败 | 标记 `session.error` + 原文摘要；不影响其它会话；可要求完整重同步 |
| 磁盘满 | 停止汇总（背压），控制台红警；daemon 侧 spool 保留 |
| 下发冲突 | 失败 `conflict`，**不重试**；用户可 `force` |
| 导入目标不支持 | `unsupported`，提示替代（如目标 pi） |

### 5.2 目录布局

```text

├── hub-service.json                                  # hub-service 配置（也支持 .yml）
├── hub.db                                    # SQLite 索引/控制态（可重建）

│   └── sessions/                             # 与 pi agentDir/sessions 同构
```

**provenance 目录名**：

```text
<piEncodedCwd 去掉结尾 "--">--h-<hostSlug>-<agentSlug>[--<instanceSlug>]--

例：/home/dev/proj → --home-dev-proj--h-laptop-pi--
    D:\work\app    → --D--work-app--h-winbox-opencode--
```

- 由 pi 原生编码派生；同一 (host, agent, instance, cwd) 恒定；不同来源永不共用；
- 改主机名不回首改目录（用 DB 显示名）。

### 5.3 会话 ID 与命名

```text
hubSessionId = "hs_" + base32(blake2s-128(hostId + "\0" + agentInstanceId + "\0" + nativeSessionId))
              小写、无填充、去掉易混字符，固定 26 字符
```

- **确定性**：同一 native session 重采多少次都是同一 hub id；
- **命名空间**：不同主机的同名 native id 不撞车；
- **header.id = 文件名后缀**（文件命名一致）；
- **header.timestamp = native 会话创建时间**；
- **header.cwd = native 原始 cwd**（保留项目归属；console 显示 origin）；
- **header.parentSession**：父会话已映射则写 hub 路径；否则删除该字段，DB 记 `native_parent`。

### 5.4 canonical 条目与合并语义

canonical = **pi v3 entries**，只允许 11 类：

`message` / `model_change` / `thinking_level_change` / `usage` / `compaction` / `branch_summary` /
`custom` / `custom_message` / `context_edit` / `label` / `session_info`。

**链式约束**：hub 侧统一拉平成**单链**（首条 `parentId: null`）。原生分支在 daemon 归一阶段处理：

1. 正文取主分支；被丢弃分支不进镜像，DB 记 `dropped_branches`；
2. 原文不动（native 存档是权威）；需要完整分支时走「原生快照」。

**合并算法（hub 侧，`POST /sync`）**

```text
输入：mode(delta|full), since, entries[]（按源顺序）, session 元数据
1) 校验：每条 entry 必须有 id/type/timestamp/parentId；单行 ≤ 8 MiB；
   内联整批 ≤ 16 MiB（压缩后）/ 64 MiB（解压后），更大走 upload（001 §4.5）
2) 若 mode=delta：
     - 允许 `timestamp >= since`；`timestamp < since` → 422 entry_before_since
       （`since` 的排他选择与同毫秒 tie-break 由 daemon 完成；hub 只按 entryId 去重）
     - 对每条：查 (entryId) 是否已存在
         · 不存在 → 追加候选
         · 存在且 contentHash 相同 → 跳过（幂等）
         · 存在但 contentHash 不同 → 源历史被改写 → 409 rewrite_detected
3) 若 mode=full：
     - 生成新的镜像文件（temp）→ 用本批 entries 重建单链 → rename
4) 追加写入（delta）：单事务 + per-session 写锁；每批一次 fsync
5) 更新 session.last_timestamp = max(entry.timestamp)，last_entry_id = 末条 id
6) 失效 transcript 缓存 / 更新搜索索引
7) 返回 {merged, skipped, lastTimestamp, lastEntryId, status}
```

**时间戳语义**

- manifest 的 `updatedAt` 是 agent 自己的会话更新时间（用于 `skipped` 判定）；
- hub 返回的 `lastTimestamp` 是已落盘最后一条 entry 的 timestamp（缺失 = 完整同步）；
- 同毫秒用 `lastEntryId` tie-break；
- 适配器无法给出稳定顺序 → `mode=full`。

### 5.5 写入与一致性

| 场景 | 写法 | 理由 |
|---|---|---|
| 增量追加 | `O_APPEND` 单行 JSON + 每批 fsync | 顺序写、可恢复 |
| 源改写 / 完整同步 | 写 `*.jsonl.tmp` → `rename` | 原子替换；inode 变化使缓存失效 |
| 会话删除 | 删镜像 + DB 墓碑 | 列表消失；保留水位 |
| 并发 | per-session 写锁（异步队列） | 避免交错写坏行 |

**校验**：header 合法、entry 字段完整、id 唯一、parentId 可解析、单行 ≤ 8 MiB。
失败 → 整批拒收（`422`）。

### 5.7 保留、配额与 GC

| 策略 | 默认值 | 说明 |
|---|---|---|
| 保留 | **30 天** | 可按 host/agent/pin 覆盖 |
| 单会话上限 | 32 MiB | 超出截断最早的 tool 输出正文并标 `truncated` |
| 大附件（base64） | 首版内联；单条 > 4 MiB 截断并标记 | Phase 2 评估 blob 外置 |
| 主机配额 | 2 GiB | 超限停止汇总 + 告警（daemon spool 保留） |
| 删除级联 | 删 host → 保留 30 天（墓碑） | 支持彻底清除 |
| 重同步 | `POST /api/hub/sessions/:id/resync` | 要求 daemon 对该会话 `mode=full` |

> ⚠️ 50k 会话 + 20M 条目时，`entries_fts`（或回退表）是主要增长点；transcript 不落库；需压测（⬜ V17）。

### 5.8 只读边界

- hub 只写 `~/.pi-agent-hub/agent/sessions/**` 与 `~/.pi-agent-hub/hub.db`；
- 不写任何主机上的 native session（例外：`import` 由 daemon 在**目标机新建**文件，见 §10.3）；
- 查看路径（console → API）只有 GET；没有「保存」「编辑」「删除会话」接口（删除只针对 host 墓碑/保留策略）。

## 6. 会话查看（hub-service 读取 + hub-console 渲染）

> 本章是**数据面与渲染契约**；页面与交互见 §11。

### 6.1 只读读取 API

**实现**：hub-service 通过 `@earendil-works/pi-coding-agent` 的 `SessionManager.listAll(dir)` / `open(path)`
读取 JSONL（只读 API），由 `transcript/normalize` 规范化为块；数据目录为
`~/.pi-agent-hub/agent/sessions`（等价于 pi 的 `agentDir/sessions`）。**不调用**任何写入/agent 会话方法，
也不启动 agent 进程。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/hub/sessions` | 列表：host/agent/项目/标题/时间/条目数/状态；支持过滤与游标分页 |
| GET | `/api/hub/sessions/:id` | 元数据：header、来源、水位、模型/用量汇总、错误 |
| GET | `/api/hub/sessions/:id/transcript?tail=100&before=<seq>` | 正文分页：取最近 N 条（按 seq 升序返回），`before` 向前翻页 |
| GET | `/api/hub/sessions/:id/blocks/:seq/:blockIndex/raw` | 取块原文（被截断的工具输出/长文本） |
| GET | `/api/hub/sessions/:id/images/:seq/:blockIndex` | 取图片字节（base64 解码后按需返回） |
| GET | `/api/hub/sessions/:id/stats` | 用量/成本/条目分类统计 |
| GET | `/api/hub/search?q=&host=&agent=&limit=` | 全文搜索（FTS5 或 LIKE 回退），返回片段 + 定位 |

**参数约定**

- `tail` 上限 500，默认 100；响应按 `seq` **升序**返回便于渲染；`before` 为 `seq`（不含），取更早一页；
- 响应含 `hasMore`（更早是否还有）与 `oldestSeq`/`newestSeq`；
- 列表分页用 `cursor`（不透明串），避免 offset 深翻；
- 所有响应 `Cache-Control: no-store`；正文不在浏览器落盘缓存。

### 6.2 transcript 规范化

hub-service 把 pi entries 变成 UI 友好的 `items[]`（每条 entry 一个 item，含若干 blocks）：

```ts
type TranscriptItem = {
  seq: number;              // 单调，用于分页/定位
  entryId: string;
  type: string;             // pi entry type
  ts: number;               // ms
  role?: "user" | "assistant" | "tool" | "system" | "meta";
  blocks: Block[];
};

type Block =
  | { kind: "text"; text: string; markdown?: boolean }
  | { kind: "thinking"; text: string }
  | { kind: "toolCall"; callId: string; name: string; input: unknown; status: "pending" | "ok" | "error" }
  | { kind: "toolResult"; callId?: string; name: string; ok: boolean;
      preview: string; bytes: number; truncated: boolean; rawUrl?: string }
  | { kind: "image"; mime: string; url: string; width?: number; height?: number }
  | { kind: "bash"; command: string; output: string; exitCode?: number; cancelled?: boolean }
  | { kind: "summary"; summaryType: "compaction" | "branch"; text: string; tokensBefore?: number }
  | { kind: "diff"; files: Array<{ path: string; patch: string }> }
  | { kind: "meta"; label: string; detail?: string; level?: "info" | "warn" }
  | { kind: "unknown"; raw: string };
```

**映射规则（pi entries → blocks）**

| 来源 | 渲染 |
|---|---|
| `message.role=user`（文本/图片） | `text` + `image` |
| `message.role=assistant`（text） | `text`（markdown） |
| `message.role=assistant`（thinking） | `thinking`（默认折叠） |
| `message.role=assistant`（toolCall） | `toolCall`（名称 + 参数摘要 + 状态） |
| `message.role=toolResult`（文本） | `toolResult`（预览 + 原文链接；错误红色） |
| `message.role=bashExecution` | `bash`（终端样式） |
| `compaction` / `branch_summary` | `summary`（时间线分隔卡） |
| `custom_message`（display=true） | `text`（扩展消息样式） |
| `custom`（display 无关） | `meta`（可展开 raw） |
| `model_change` / `thinking_level_change` / `usage` | `meta`（时间线小标签；用量进 stats） |
| `label` / `session_info` | 不进正文（用于列表/详情/书签） |
| `context_edit` | `meta`（显示被编辑的上下文） |
| 未知类型 | `unknown`（折叠 raw JSON） |

**工具调用的适配**

- `apply_patch` 类：从参数还原 unified diff → `diff`（左右/统一视图）；
- 图片型工具结果：`image`（缩略图 + 点击放大）；
- 超长输出（> 64 KiB）：`toolResult.preview` 截断并给 `rawUrl`；
- 结构化输出（JSON）：格式化 + 可折叠；
- 失败结果：`ok=false` + 错误样式；保留原始错误文本。

**截断与安全**

- 单块文本上限 64 KiB（可配置）；超出部分走 `/raw`；
- Markdown 渲染：禁用 raw HTML；链接协议白名单 `http/https/mailto`；外链 `rel="noopener noreferrer"`；
- 代码块语法高亮；diff 只读；
- 图片只允许 `image/*`，按 `Content-Type` 返回并加 `X-Content-Type-Options: nosniff`。

### 6.3 搜索

- 索引对象：会话标题、用户/助手文本、工具名与输出预览、compaction 摘要；
- 首选 SQLite **FTS5**（⬜ 需验证 Node 内置 SQLite 是否启用 FTS5）；不可用则 `LIKE` + 截断扫描；
- 结果：`{sessionId, seq, entryId, snippet, ts}`；点击定位到正文（`?before=seq+1`）；
- 索引在 merge 后增量更新；`hub reindex` 全量重建。

### 6.4 性能设计

| 问题 | 措施 |
|---|---|
| 超大会话（1 万+ entry） | 服务端按 `tail/before` 分页；默认 100 条；前端虚拟列表 |
| 重复解析 JSONL | 以 `(path, size, mtime)` 为键的 LRU 解析缓存；`lastTimestamp` 变化即失效 |
| 大块正文 | 64 KiB 截断 + `/raw` 按需加载 + `Range` |
| 图片 | 缩略图（服务端可生成或前端 CSS 缩放）+ 原图按需；列表不返回 base64 |
| 列表 50k 会话 | SQLite 索引 + 游标分页；默认只返回需要的列 |
| 搜索 | FTS5；无则后台建 inverted index（Phase 3） |

### 6.5 只读保证

- 会话读取 API **只有 GET**；没有写入/删除会话的端点；
- console 不提供编辑、重命名、删除、发消息的正文入口（发消息是独立的「下发」动作，走 §10）；
- 服务端不调用 agent 控制接口，也不启动任何 agent 进程；
- 所有 native 存档由 daemon 只读采集，hub 不写回。

### 6.6 渲染要点（简版）

不做独立渲染规范文档；规则固定为：

1. **块类型**：文本、思考、工具调用、工具结果、图片、bash、summary、diff、meta、unknown（§6.2）；
2. **Markdown**：`html:false` + DOMPurify；链接只允许 `http/https/mailto`；外链 `noopener`；
3. **工具输出**：默认折叠预览；> 64 KiB 截断并给「查看原文」（`/raw`）；错误红色；
4. **图片**：缩略图 + 灯箱；列表/正文 JSON 不内联 base64；
5. **分页**：正文按 `seq` 分页 + 虚拟列表；顶部「加载更早」；
6. **未知类型**：折叠 raw JSON，不隐藏数据；
7. **只读**：正文没有编辑/删除/发送入口；下发是独立弹窗。

## 7. sync-daemon

### 7.1 职责

1. **发现**：扫描本机 agent 实例与存档位置（可手工覆盖）；
2. **采集**：文件监听 + 尾部读取 + agent API 轮询；
3. **归一**：异构存档 → canonical pi entries（含脱敏）；
4. **同步**：`manifest → 时间戳差分 → POST /sync`，失败进 spool；
5. **接收**：保持 SSE 连接，处理 `deliver` / `import` 事件；
6. **执行**：调 agent 的 ACL/ACP/原生 API，回执状态；
7. **自省**：版本/能力/健康上报。

### 7.2 适配器契约（由 `sync-plugin-*` 实现）

daemon 不直接解析任何 agent 格式；每个 agent 一个插件进程。逻辑接口（对应 §7.11 的 JSON-RPC 方法）：

| 方法 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `initialize` | `protocolVersion`, `daemonVersion`, `config` | `pluginVersion`, `capabilities` | 握手/版本协商 |
| `detect` | `env`（路径、代理、环境变量白名单） | `AgentInstance[]` | 探测本机实例（可多份） |
| `list_sessions` | `agentId` | `NativeSessionMeta[]` | **全部**历史会话（含已结束） |
| `read_session` | `agentId`, `nativeId`, `since?`, `lastEntryId?`, `workDir` | `SessionChunk` 或 `{entriesPath, sha256, count}` | 差分/全量；大包走临时文件 |
| `watch`（可选） | `agentId` | 通知 `session_changed {nativeId}` | 无 watch 时 daemon 轮询 |
| `deliver` | `agentId`, `nativeId`, `message`, `images`, `policy`, `force` | `DeliverResult` | 调 agent 的 ACL/ACP/API |
| `import_session` | `agentId`, `bundlePath`, `targetCwd` | `ImportResult` | 新建会话 |
| `export_native` | `agentId`, `nativeId`, `format`, `workDir` | `{nativePath, sha256, bytes}` | 同 kind 导入的原生快照（Q5） |
| `shutdown` | — | — | 有序退出 |
| `ping` | — | `pong` | 健康检查 |

**canonical 输出**：pi v3 entry 数组（不含 header）、已线性化、时间戳 ISO 8601、单会话内 id 唯一。

**能力位**（`initialize.capabilities`）：

```jsonc
{ "collect": true, "deliver": true, "import": true, "losslessImport": true,
  "controlInterface": "acp | native-api | cli | null",
  "readStrategy": ["storage", "api", "acp"],
  "deliveryStrategy": ["acp", "api"],
  "exportNative": true, "largeReadMode": "temp-file | inline", "watch": true }
```

**契约纪律**

- `list_sessions` 必须包含所有可见会话；删除单独上报（§4.4）；
- `read_session(since)` 幂等：同一 `(since, lastEntryId)` 返回同一批；
- `deliver` 在会话被外部改动/不可用时返回明确错误，不得硬写存档；
- `import_session` 必须新建 id，永不覆盖；
- 插件不直连 hub、不依赖 hub 私有字段；脱敏由 daemon 统一执行。

### 7.3 采集与变更检测

| agent | 存档读取 | 变更触发 | 备注 |
|---|---|---|---|
| pi | `<agentDir>/sessions/**/*.jsonl` | `fs.watch` + 1 s 去抖 + 15 s 兜底 | 追加式；尾部按偏移读 |
| opencode | **直读 SQLite（V2/V1）**；不可读回退 `opencode serve` HTTP | 本地事件流（SSE）或 5 s 轮询 | 版本适配见 §8.2 |
| dsh | 本地 dsh host `/api`；无 host 时读 `.jsonl`（需 zstd） | 本地 WS 事件（仅 daemon↔本机 host；⬜）或 5 s 轮询 | root 编码约束（C-4） |
| claude/codex | ⬜ 待适配（ACP/存档格式确认） | ⬜ | 本期只留契约 |

**存活检测**（仅展示与下发策略，不作硬保证）：pi 看文件 mtime 启发式；opencode/dsh 看 server 状态（⬜）。

### 7.4 汇总流程（核心）

**阶段 A：清单（manifest）**

```ts
const payload = await Promise.all(agents.map(async (inst) => ({
  agentId: inst.id,
  kind: inst.kind,
  sessions: (await inst.listSessions()).map((s) => ({
    nativeId: s.nativeId,
    updatedAt: s.updatedAt,
    title: s.title,
    cwd: s.cwd,
    state: s.state,            // active|idle|missing
  })),
})));

const res = await hub.manifest({ agents: payload });
// res.sessions: [{ agentId, nativeId, hubSessionId, lastTimestamp, lastEntryId, status }]
```

**阶段 B：差分读取**

```ts
for (const item of res.sessions) {
  if (item.status === "skipped") continue;
  const chunk = await plugin.read_session(item.agentId, item.nativeId, {
    since: item.lastTimestamp ?? undefined,          // null → 全量
    lastEntryId: item.lastEntryId ?? undefined,
  });
  if (chunk.entries.length === 0 && item.lastTimestamp !== null) continue;
  await hub.sync(item.hubSessionId, {
    since: item.lastTimestamp,
    mode: chunk.mode,
    session: chunk.meta,
    entries: chunk.entries,
  });
}
```

**阶段 C：hub 合并**：见 §5.4。`409 rewrite_detected` → 立即对该会话改发 `mode=full`。

**幂等/重试**：同一批可重复提交（entryId 去重）；失败进 spool，按 `(hubSessionId, since)` 重放。

**时间戳边界**

- `since` 是排他上界：只发 `timestamp > since`；
- 同毫秒用 `lastEntryId` 在源存档中的位置 tie-break；
- 源无法给出顺序 → `mode=full`；
- 源历史被改写（同 id 不同内容）→ hub 回 `rewrite_detected` → `mode=full`。

### 7.5 下发执行

```text
SSE event: deliver
  → 幂等检查（deliveryId 已执行？直接回成功）
  → 校验 session 状态与空闲（§10.2）→ conflict 则回失败
  → 调 agent 控制接口：
      pi:        spawn `pi --mode rpc --session <path>` → get_state 校验 → prompt → 等 agent_settled
      opencode:  ACP（`opencode acp`）优先；否则 HTTP `session.prompt`
      dsh:       ⬜ 待确认「对已有 session 发消息」的方法
      claude/codex: ACP `session/prompt`（⬜ 待适配）
  → 立即触发该会话一次同步（manifest 单项 → 差分 → POST /sync）
  → POST /api/v1/deliveries/{id}/ack
  → POST /api/v1/deliveries/{id}/result{state, nativeMessageId?, error?}
```

**pi 细节**（✅ 接口存在）：

- `pi --mode rpc --session <nativePath>`；`get_state` 校验 `sessionFile` 一致；
- `prompt {message, images?}`；等 `agent_settled`（或 `agent_end` + 空闲阈值）；
- 关闭 stdin 有序退出；超时 SIGTERM/SIGKILL；
- ⚠️ **单写者（C-1）**：用户可能同时操作同一会话 → 默认 `idle-only`（近 120 s 无写入）；
  `force` 需二次确认；更严格用 `managed-only`。

**opencode**：**ACP 优先**（`opencode acp`）；无 ACP 时 `session.prompt`；无运行中 server 时按配置临时拉起。
**dsh**：⬜ 需确认 `/api` 方法与 `sessionID` 语义（§8.3）。

### 7.6 导入执行

1. 收到 SSE `import`（`importId`、`bundleUrl`、`targetAgentId`、`targetCwd`）；
2. `GET bundle`（支持 `Range`，大包分块）；
3. 校验目标 agent 可用、目标 cwd 可写、目标 id 不存在；
4. 调插件 `import_session`；
5. 回执 `{nativeId, nativePath, warnings[]}`；
6. 立即触发该会话同步（hub 里以新 hub session 出现，带 `imported_from`）。

### 7.7 SSE 客户端

| 项 | 设计 |
|---|---|
| 连接 | `GET /api/v1/events`，`Accept: text/event-stream`，Bearer |
| 重连 | 服务端 `retry: 3000`；客户端指数退避（1s→60s）+ 抖动 |
| 补发 | 记录最后 `id`；重连带 `Last-Event-ID`；hub 从每主机缓冲重放 |
| 心跳 | hub 每 15 s `: ping`；客户端 45 s 无数据视为断线 |
| 事件 | `deliver` / `import` / `reset`（缓冲过期） |
| 丢失兜底 | `reset` → `GET /api/v1/deliveries?state=pending` + imports |
| 幂等 | 事件携带业务 id；执行前查本地已完成表 |
| 并发 | 同 session 串行；不同 session 可并发（上限可配） |

### 7.8 离线缓冲

| 机制 | 设计 |
|---|---|
| 同步 spool | `<daemonData>/spool/<hubSessionId>/<since>.jsonl.gz`，上限 512 MiB；超限丢最旧并告警 |
| 水位 | 只在 hub `200` 后推进本地 `lastSyncedTimestamp` |
| 重试 | 网络/5xx 指数退避（最多 5 次）；`401` 停止并提示更新 token；`409` 改全量 |
| 时钟 | UTC 毫秒；hub 以服务端时间做 TTL |

### 7.10 部署形态与守护

| 平台 | daemon | 守护方式 | 托盘 |
|---|---|---|---|
| **Windows** | 用户级 Node 进程（`node.exe` + daemon） | **Tauri 托盘**拉起并监督；托盘随登录启动 | ✅ Tauri（系统托盘） |
| **macOS** | 用户级 Node 进程 | **Tauri 托盘**拉起并监督；登录项启动 | ✅ Tauri（菜单栏，`LSUIElement`） |
| **Linux** | Node 进程 | **pm2**（`pm2 start/save/startup`）；systemd 可选 | ❌ 不提供托盘 |
| headless/服务器 | Node 进程 | systemd / pm2 / 容器 | ❌ |
| 试用/开发 | `npx @pi-agent-hub/sync-daemon run` | 前台 / pm2 | ❌ |

- **Win/macOS 不注册系统服务**：daemon 是用户级子进程，能直接读 `~/.pi` 等用户存档；
  托盘退出 → 默认停止 daemon（可选「关闭窗口后继续运行」，由托盘设置决定）。
- **Linux 固定组合**：`node + pm2 + @pi-agent-hub/sync-daemon`；pm2 负责开机自启/崩溃重启/日志；
  systemd 作为等价替代（用户级）。
- **安装包（Win/macOS）**：Tauri 托盘 + 内置 Node 运行时 + daemon + 默认插件，一个安装包；
  也可不装托盘，用 `npm i -g`/`npx` 单独跑 daemon。
- **运行账号**：与 agent 同一用户；不使用 LocalSystem/root。
- **配置目录**：统一 `~/.pi-agent-hub/`（Windows `%USERPROFILE%\.pi-agent-hub\`）；
  hub 用 `hub-service.json`，daemon 用 `sync-daemon.json`；日志/令牌 `0600`。
- **单实例**：daemon 取锁文件/控制端口，重复启动直接退出；托盘单实例锁避免双托盘。
- **token 由配置提供**：hub-service 的 `daemonTokens[]` 与每个 daemon 的 `hub.token` 一一对应；
  导入只写 `import.allowedRoots`；SSE 只接受 `deliver`/`import`；本地审计 `audit.log`。

### 7.11 插件机制（Node 子进程 + npm 包）

**为什么子进程（C-9）**

| 方案 | 结论 | 理由 |
|---|---|---|
| **子进程 + JSON-RPC/stdio** | ✅ | 崩溃隔离；插件可独立升级；npm 分发；不污染 daemon 事件循环/内存 |
| 同进程 `import()` | ❌ | 插件异常/泄漏拖垮 daemon；无法按插件限权/限内存 |
| Worker Threads | 🔶 | 隔离弱于子进程；native addon 崩溃仍可拖垮进程 |
| 原生动态库 | ❌ | 引入第二种语言/ABI；与「减少语言」目标冲突 |

**npm 包布局**

```text
node_modules/@pi-agent-hub/
├── sync-plugin-pi-agent/
│   ├── package.json          # name/bin/piAgentHub 元数据
│   └── dist/main.js          # bin 入口（JSON-RPC server）
├── plugin-opencode/
└── plugin-dsh/
```

```jsonc
// package.json（片段）
{
  "name": "@pi-agent-hub/sync-plugin-pi-agent",
  "version": "0.1.0",
  "bin": { "pi-agent-hub-sync-plugin-pi-agent": "dist/main.js" },
  "piAgentHub": {
    "kind": "pi",
    "protocolVersion": "1.0",
    "minDaemonVersion": "0.1.0",
    "capabilities": { "collect": true, "deliver": true, "import": true,
                      "losslessImport": true, "exportNative": true,
                      "controlInterface": "native-api" },
    "permissions": { "fsRead": ["~/.pi/agent/**"], "fsWrite": ["~/.pi/agent/sessions/**"],
                     "net": ["127.0.0.1:*"], "spawn": ["pi"] },
    "timeouts": { "list": 30, "read": 120, "deliver": 600, "import": 1800 },
    "maxConcurrency": 2
  }
}
```

- **发现**：以配置 `plugins` 声明为准；从 `pluginRoot/node_modules`、安装包内置 `node_modules`、全局 npm 解析；
  只加载 `pluginAllowlist` 命中的包；插件名/版本显示在 console 与托盘配置界面。
- **版本**：npm semver + `protocolVersion` 主版本；不兼容 → 插件 `disabled` 并告警。
- **签名（可选，默认不做）**：npm provenance/`npm audit signatures`；`requireSignedPlugins=true` 时才强制校验。

**配置与加载（参考 `opencode.json`）**

```jsonc
// ~/.pi-agent-hub/sync-daemon.json（或 %USERPROFILE%\.pi-agent-hub\sync-daemon.json）
{
  "plugins": [                       // 兼容 opencode：`plugin` 亦可作为别名
    "@pi-agent-hub/sync-plugin-pi-agent",
    { "package": "@pi-agent-hub/sync-plugin-opencode@0.2.0",
      "options": { "server": "http://127.0.0.1:4096" } },
    "./local/plugin-dsh"
  ],
  "pluginInstall": true,                       // 缺失时允许动态 npm 安装
  "pluginAllowlist": ["@pi-agent-hub/*"],      // 只允许这些 spec
  "pluginRoot": "~/.pi-agent-hub/plugins",     // 安装/解析根（含 package.json + lock）
  "agents": { "pi": { "enabled": true, "instances": [] } }
}
```

- **参考 opencode**：`plugin`/`plugins` 支持字符串或 `{ package, options }`；本地绝对路径直接加载；
  非本地包用 npm `resolve`/`add`（✅ `opencode/packages/core/src/plugin/module.ts:99-120`、
  `opencode/packages/util/src/npm.ts:27-28`）。
- **解析顺序**：
  1. 绝对/相对路径 → 本地插件（不安装）；
  2. 从 daemon 自己的 `node_modules`、`pluginRoot/node_modules`、`npm root -g` 解析；
  3. 解析失败且 `pluginInstall=true` 且命中 `pluginAllowlist` → 在 `pluginRoot` 执行
     `npm install --ignore-scripts --no-audit --no-fund --save-exact <spec>`（`pluginRoot` 内有 package.json + 锁文件），再解析；
  4. 校验包内 `piAgentHub` 元数据（kind/protocolVersion/bin/capabilities）；缺失 → `plugin_invalid`；
  5. 拉起子进程（§7.11 生命周期）。
- **版本**：spec 建议带 `@version`；安装结果写入 `pluginRoot/package-lock.json`；升级需改配置或显式 `npm update`。
- **安全**：默认只允许 `@pi-agent-hub/*`；第三方需显式加入 allowlist；`--ignore-scripts`；`npm audit signatures`；
  插件目录仅管理员可写；离线时缺失包 → `plugin_not_found`（console/托盘可见）。
- **插件形态**：优先**纯 JS/TS**（无原生模块）；确需原生模块时随安装包预编译分发，不在用户机现场编译。
- **安装位置**：Win/macOS 安装包内的 `node_modules` 在应用资源目录（只读、已签名），**动态安装只写 `pluginRoot`**
  （用户数据目录）；解析顺序：`pluginRoot` → 应用内置 → 全局 npm。
- **内置 npm**：随包 Node 发行版包含 npm；动态安装用 `node <resources>/npm/bin/npm-cli.js install ...`，
  不依赖系统 npm。
- **配置热更新**：watch `sync-daemon.json` → 计算插件集合差异（新增/移除/版本变化）→ 安装/停止/重建子进程；
  不重启 daemon。
- **错误可见**：安装失败/协议不兼容/崩溃循环 → 插件状态 `error|disabled`，console 与托盘配置界面显示原因。

**传输与帧**

- JSON-RPC 2.0 over **stdio**，**NDJSON**（一行一个 JSON）；stdout 只放协议，日志走 stderr；
- 请求/响应/通知；`id` 单调；错误用 JSON-RPC `error {code, message, data}`；
- 方法见 §7.2；
- 大负载：插件把 canonical NDJSON 写到 `workDir` 临时文件，返回 `{entriesPath, sha256, count}`，
  daemon 流式读取、校验、脱敏；避免 stdio 大包。

**生命周期与监督**

1. `child_process.spawn(process.execPath, [bin], { stdio: ["pipe","pipe","pipe"] })`；
2. 按 agent 实例拉起（一个实例一个进程；空闲 5 min 回收）；
3. `initialize` 握手（协议版本、配置、能力）；`config` 取自 daemon 的 `[agents.<kind>]`；
4. `ping` 每 30 s；失败/退出 → 指数退避重启（1s→60s，10 min 内最多 5 次）；
5. 崩溃循环 → 插件 `disabled`，console 告警；不影响其它插件与 daemon；
6. 升级：`npm i -g`/更新依赖 + 重启插件；daemon 不需要重启。

**资源与安全**

- 子进程 `--max-old-space-size` 限制；超时 kill；stdout/stderr 采集到 daemon 日志；
- 同用户运行；`permissions` 用于配置审计；可选 Node **Permission Model**（`--experimental-permission`）
  限制 fs/child_process（注意：插件需要 spawn agent/访问 loopback，需逐项放行；首版默认关闭）；
- 插件不得监听公网端口；`net` 仅 loopback；
- 插件目录/`node_modules` 只允许管理员写入；`npm ci` + 锁文件 + 审计。

**测试**

- `@pi-agent-hub/sync-plugin-fixture`（故意崩溃/超时/脏输出）验证监督；
- 每个插件带黄金样本（脱敏）→ canonical 输出快照；
- 三平台 CI 跑 list/read/deliver/import 契约。

### 7.12 托盘（Tauri）与配置界面

**为什么用 Tauri（而非 Electron）**

| 方案 | 安装体积 | 运行时 | 结论 |
|---|---|---|---|
| **Tauri v2** | **~5–15 MB**（不含内置 Node/daemon） | 系统 WebView（WebView2 / WKWebView）+ Rust | ✅ **推荐** |
| Electron | ~80–120 MB | 自带 Chromium + Node | ❌ 太重（用户明确否决） |
| Wails（Go） | ~10–20 MB | 系统 WebView + Go | 🔶 新增 Go |
| `systray`/`trayicon` | 小 | Node + 原生/Go 辅助 | 🔶 菜单/配置界面能力弱 |
| 无托盘 | — | — | ❌ 不满足常驻状态栏 |

Tauri 只增加**构建期** Rust 工具链；运行期是小型原生 App + 系统 WebView，符合「少语言、轻量」目标。

**Tauri 架构**

```text
sync-daemon-tray（Tauri App，Win/macOS）
├─ Rust 主进程
│   ├─ 托盘图标/菜单（TrayIconBuilder + Menu）
│   ├─ 单实例（tauri-plugin-single-instance）
│   ├─ 开机自启（tauri-plugin-autostart 或登录项）
│   ├─ 监督：spawn node daemon、日志、健康检查、重启退避、退出时停止
│   └─ 配置读写：sync-daemon.json（插件、agent 路径、策略）
└─ WebView（静态 HTML/CSS/JS，无前端框架；设计令牌与 console 对齐）
    └─ 配置界面：插件列表/安装、agent 目录、同步策略、日志查看
```

- **职责边界**：托盘只做 **daemon 守护 + 配置界面 + 状态展示**；不采集、不解析存档、不直连 hub。
- **健康检查**：读 daemon 的 `daemon-control.json` → `GET /local/status`；失败则按 1s/5s/15s/30s 重启；
  连续失败 → 托盘显示红点 + 日志入口。
- **生命周期**：托盘启动 → 读取配置 → spawn daemon；托盘退出 → 先 `POST /local/quit`，超时再 kill；
  设置项「关闭窗口后继续运行」控制是否保留后台 daemon。
- **配置界面**（WebView）：
  - 插件：当前列表、来源（本地/npm）、版本、状态；添加/移除/重装；
  - agent：实例目录（`~/.pi/agent`、opencode data、dsh root）、启停；
  - 同步：间隔、脱敏规则文件、spool 上限；
  - 日志：最近 N 行 + 打开日志目录；
  - 保存后写 `sync-daemon.json`，由 daemon watch 热生效（插件变更会重启对应子进程）。
- **打包（单安装包）**：
  - Tauri `resources` 内放：`node/`（对应平台 Node 运行时 + npm）、`daemon/`（dist + 依赖）、`plugins/`（默认插件）；
  - Windows：NSIS/MSI；macOS：`.dmg`/`.pkg`；均包含托盘 + Node + daemon + 插件；
  - **Windows**：依赖 **WebView2 Runtime**（Win11/新版 Win10 自带；安装器带 bootstrapper 兜底）；
  - **macOS（发布阶段，本期暂缓）**：内嵌 node 与 App 一起签名并公证；hardened runtime 需为 Node 添加
    `com.apple.security.cs.allow-jit` 等 entitlement；
  - **Windows（发布阶段，本期暂缓）**：node.exe 与安装包 Authenticode 签名；
  - 体积预估：Node+npm ~60–90 MB + daemon/依赖 ~30–60 MB + Tauri ~10 MB → **安装包约 100–160 MB**（⬜ 实测）。
- **GitHub CI**：`tauri-apps/tauri-action` + matrix（`windows-latest`、`macos-14` arm64、`macos-13` x64）；
  下载并校验 Node 运行时 → `pnpm install --frozen-lockfile` → 构建 daemon/插件 → 组装 resources → 发布
  （签名/公证本期暂缓）。
- **Linux**：不构建托盘；交付 `node + pm2 + daemon`。

**本地管理 API**（daemon → tray）

- daemon 绑定 `127.0.0.1:<随机端口>`，写 `daemon-control.json`（`0600`）：`{ "port": 51234, "token": "..." }`；
- `GET /local/status`（在线/暂停/插件/队列/最后同步）；
- `POST /local/pause` / `/local/resume` / `/local/sync-now`；
- `GET /local/logs?tail=200`；`POST /local/quit`；
- 托盘读取 token 文件后调用；文件权限 + 随机 token 双重保护。

### 7.13 Node 运行时、npm 分发与 Linux 守护

| 项 | 方案 |
|---|---|
| Node 版本 | **≥ 22.19**（pi SDK engines）；推荐 **Node 24 LTS**；启动检测 |
| Win/macOS 分发 | **随 Tauri 安装包内置** Node + daemon + 默认插件；一个安装包 |
| Win/macOS 独立运行 | `npm i -g @pi-agent-hub/sync-daemon@x.y.z`；`npx ...` 仅试用 |

**Linux（pm2）**

```bash
npm i -g @pi-agent-hub/sync-daemon@0.1.0
pm2 start "$(npm root -g)/@pi-agent-hub/sync-daemon/dist/cli.js" --name pi-agent-sync -- run --config ~/.pi-agent-hub/sync-daemon.json
pm2 save
pm2 startup            # 生成开机自启（systemd/launchd）
pm2 install pm2-logrotate
```

- pm2 以**运行 agent 的用户**启动（不要 root）；`~/.pi` 可读；
- systemd 等价替代：`ExecStart=/usr/bin/node <global>/dist/cli.js run`、`Restart=always`。

**Win/macOS 独立运行（无托盘）**

- `npm i -g` 后用登录任务（Task Scheduler / launchd）或 `pm2` 启动；
- 需要托盘时用安装包；不需要托盘时 npm 路线完全可用。

**npx 说明**：`npx` 按需下载/缓存，不适合长期服务；仅用于试用与 CI 冒烟。

**单实例与升级**

- daemon 锁文件/控制端口保证单实例；pm2/托盘重复拉起不会双开；
- 升级：安装包升级（Win/macOS）或 `npm i -g` + 重启（Linux）；插件独立升级。

### 9.3 同步 API（REST）

**`POST /api/v1/sync/manifest`**

```jsonc
// 请求
{
  "agents": [
    { "agentId": "a_pi_laptop", "kind": "pi", "version": "1.2.0",
      "sessions": [
        { "nativeId": "019a...", "updatedAt": 1762700000000,
          "title": "refactor auth", "cwd": "D:\\work\\app", "state": "idle" }
      ] }
  ]
}

// 200 OK
{
  "serverTime": 1762700001000,
  "sessions": [
    { "agentId": "a_pi_laptop", "nativeId": "019a...", "hubSessionId": "hs_7f3k...",
      "lastTimestamp": 1762699500000, "lastEntryId": "ent_9", "status": "ok" },
    { "agentId": "a_pi_laptop", "nativeId": "019b...", "hubSessionId": "hs_2m9q...",
      "lastTimestamp": null, "lastEntryId": null, "status": "new" }
  ]
}
```

- `lastTimestamp: null` → **完整同步**；
- `status`: `new` / `ok` / `skipped`（`updated_at` 未变）/ `full`（强制完整同步）/ `quota` / `error`；
- 主机身份以**令牌绑定**为准；
- `state:"missing"` 只表示本地存档暂不可读，**不代表删除**；删除必须显式 `/deleted`；
- `idempotencyKey` 可选：同 key 重复请求返回上次结果。

**`POST /api/v1/sync/sessions/{hubSessionId}`**

```jsonc
// 请求（delta）
{
  "agentId": "a_pi_laptop",
  "nativeId": "019a...",
  "since": 1762699500000,
  "mode": "delta",                       // 或 "full"
  "session": { "cwd": "D:\\work\\app", "title": "refactor auth",
               "createdAt": 1762600000000, "updatedAt": 1762700000000 },
  "entries": [ /* canonical pi v3 entries，按源顺序 */ ],
  "truncated": false,
  "idempotencyKey": "a_pi_laptop:019a...:1762699500000"
}

// 200 OK
{ "merged": 12, "skipped": 0,
  "lastTimestamp": 1762700000000, "lastEntryId": "ent_21", "status": "ok" }

// 409 Conflict：源历史被改写
{ "error": "rewrite_detected", "entryId": "ent_7",
  "message": "entry content differs from stored copy", "retryable": true }
```

**`POST /api/v1/sync/sessions/{id}/deleted`**：源会话已删除（墓碑）。
**`POST /api/v1/sync/sessions/{id}/resync`**：console 触发，hub 在下次 manifest 返回 `status:"full"`。

**合并规则**见 §5.4；**鉴权** Bearer；**限流** 120 req/min/主机（突发 20），超出 `429 + Retry-After`。

### 9.4 SSE API（下行）

**`GET /api/v1/events`**（`Accept: text/event-stream`，Bearer）

```text
retry: 3000

id: 10231
event: deliver
data: {"deliveryId":"dlv_...","agentId":"a_pi_laptop","nativeSessionId":"019a...",
       "hubSessionId":"hs_7f3k...","message":"继续把测试补上","images":[],
       "policy":"idle-only","createdAt":1762700000000}

id: 10232
event: import
data: {"importId":"imp_...","bundleUrl":"/api/v1/bundles/blb_...",
       "targetAgentId":"a_open_laptop","targetCwd":"D:\\work\\app"}

id: 10233
event: export_native
data: {"exportId":"exp_...","transferId":"trf_...","agentId":"a_pi_laptop",
       "nativeSessionId":"019a...","format":"pi-jsonl-v3"}

: ping
```

规则：

- **单主机一条活跃 SSE**；新连接**顶替**旧连接（hub 关闭旧流）；
- 每条事件有单调 `id`，写入 `sse_events`；`Last-Event-ID` 重放最近 N 条（默认 1000 条 / 1 h）；
- 缓冲过期 → `event: reset`，daemon 用 REST 拉 pending 补齐；
- 心跳 15 s；`retry: 3000`；
- 反代：关闭响应缓冲（`X-Accel-Buffering: no`）、禁用压缩、读超时 ≥ 60 s；
- **SSE 不承载回执**：ack/result 一律 REST。

**daemon 侧 REST**

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/deliveries?state=pending` | 断线补齐 |

### 9.6 调度、限流与幂等

- **每主机 SSE 1 条**；事件按到达顺序入 `sse_events`；
- **每会话串行**：同一 native session 的 `deliver` 与 `import` 互斥；
- **每主机并发**：默认 2 个执行任务；
- **全局并发**：16；
- **超时**：deliver 10 min；import 30 min；
- **重试**：仅 `retryable`（网络/超时/daemon 重启），指数退避最多 3 次；`conflict`/`unsupported` 不重试；
- **限流**：`/api/hub/deliveries` 每用户 10 req/s；同步 API 每主机 120 req/min；
- **幂等键**：delivery/import 由 console 生成 UUID；重复提交返回同一任务。

```jsonc
{
  "server": { "port": 8443, "publicUrl": "https://hub.example.com" },
  "users": [
    { "username": "admin",  "passwordHash": "argon2id$...", "role": "admin"  },
    { "username": "alice",  "password": "dev-only-change-me", "role": "viewer" }
  ],
  "daemonTokens": [
    { "name": "laptop-win", "token": "phk_...", "hostName": "laptop-win",
      "labels": ["dev", "windows"] },
    { "name": "mac-mini",   "tokenHash": "sha256:...", "hostName": "mac-mini" }

```

| 角色 | 权限 |
|---|---|
| `admin` | 全部：查看、下发、导入、resync、pin、force、配置重载、审计 |

- **不做 RBAC**：只有两种角色；没有用户管理 UI，用户/密码/角色在配置文件里；

- token 轮换：改配置 + reload/重启；daemon 更新 `hub.token`；
- 登录：用户名 + 密码 → HttpOnly Cookie + CSRF token；
- 审计记录 `actor_username`。

## 10. 下发与导入语义

### 10.1 下发（deliver）状态机与幂等

```
queued ──SSE 推送──► dispatched ──daemon ack──► accepted ──agent 接受──► running
   │                     │                        │                      │
   │                     └─ 重连补发/超时 ─────────┘                      ├─ settled → completed
   └─ canceled ──► canceled                                              └─ error → failed
```

| 状态 | 含义 | console 动作 |
|---|---|---|
| `queued` | hub 已接受，等待推送/重连 | 取消 |
| `dispatched` | 已写入 SSE 流（可能未送达） | 取消（尽力） |
| `accepted` | daemon 已 ack，开始调用 agent | — |
| `running` | agent 已接受 prompt | — |
| `completed` | 收到 result 且会话已同步 | 跳到会话详情 |
| `failed` | 明确失败（含 `conflict`） | 重试（新 id）/强制 |
| `expired` | 超时 | 重试 |

- **幂等**：`deliveryId` 是业务键；daemon 执行前查本地已完成表；hub 对同一 `idempotencyKey` 返回同一任务；
- **关联**：daemon 回 `nativeMessageId`（若 agent 提供）；否则 hub 用「同步后 `since` 之后第一条 user message + 文本哈希」关联；
- **SSE 重放**：重复 `deliveryId` 只回 ack，不重复 prompt。

### 10.2 并发写保护（C-1）

| 策略 | 条件 | 适用 |
|---|---|---|
| `managed-only` | 只允许 hub 导入/登记的会话 | 生产/无人值守 |
| **`idle-only`（默认）** | native session 近 `idleSeconds`（默认 120 s）无写入 | 常规 |
| `force` | 显式覆盖，console 二次确认 | 排障 |

- 检测：daemon 记录 `lastNativeWriteAt`（文件 mtime / agent 最后事件时间）；下发前复查，变化即 `conflict`；
- ⚠️ 不能完全排除竞态（用户可能在 100 ms 内开始输入）；console 必须提示「不要在两端同时操作同一会话」。

### 10.3 导入（一次性）

```
queued → preparing(bundle) → transferring → materializing → completed
                                   └──── failed (unsupported | cwd_not_allowed | invalid_bundle | io)
```

| 检查 | 失败码 |
|---|---|
| 目标 host 在线、`capabilities.import` | `unsupported` |
| 目标 cwd 存在且在 `allowedRoots` | `cwd_not_allowed` |
| 目标 id 不存在（新建） | `conflict`（重试换新 id） |
| bundle 校验（单链、首条 parentId=null） | `invalid_bundle` |
| 目标 agent 版本兼容 | `unsupported` |

**同 kind 的原生快照（`export_native`）**：

1. hub 发 SSE `export_native` → 源 daemon；
2. 源 daemon 调插件 `export_native` 生成原生文件（pi JSONL / opencode export / …）；
3. 源 daemon 上传到 `POST /api/v1/uploads`（kind=`native-snapshot`，TTL 1 h，加密在途）；
4. hub 在 bundle 的 `native.blobRef` 指向临时 blob；
5. 目标 daemon 下载并导入；hub 删除临时 blob（或 TTL 到期）；
6. hub 只保留 `sha256/size/createdAt`；**不长期保存原文**。

> ⚠️ 原生快照可能绕过 canonical 脱敏；仅同 kind、仅 admin 可发起，必须审计。

**bundle 格式**（`hub-session-bundle/1`）

```jsonc
{
  "format": "hub-session-bundle",
  "version": 1,
  "source": { "hostId":"h_...", "hostName":"laptop-win", "agentKind":"pi",
              "agentName":"default", "nativeId":"...", "hubSessionId":"hs_..." },
  "session": { "cwd":"D:\\work\\app", "createdAt":1762600000000, "title":"..." },
  "canonical": { "entries": [ /* pi v3 entries，已拉平单链 */ ] },
  "native": { "format":"pi-jsonl-v3 或 opencode-export 或 null",
              "blobRef":"blob:sha256-...", "compression":"none" },
  "lossy": [ "provider/model 元数据未迁移", "思考块已丢弃" ],
  "checksum": "sha256:..."
}
```

**pi 导入落盘**：

1. 新 `sessionId = uuidv7()`、`timestamp = now`、`cwd = targetCwd`；
2. entries 原样复制（entry id 不变），`compaction.firstKeptEntryId` 等引用保持；
3. 尾部追加 `{ "type":"custom", "customType":"pi-agent-hub.import", "data":{来源/有损}, "id":..., "parentId":"<leaf>", "timestamp":... }`
   （`custom` 不进入 LLM 上下文 ✅ `session-manager.ts:120-132`）；
4. 写 `<targetAgentDir>/sessions/<encoded cwd>/<ts>_<id>.jsonl`（临时文件 → rename）；
5. 回执 `nativeId/nativePath/warnings`。

**opencode 导入**：`session.import`（⬜ 字段与 cwd 绑定实测）。
**dsh 导入**：本期 `unsupported`；建议导入到目标机 pi。

### 10.4 错误码

| 码 | 场景 | 重试 |
|---|---|---|
| `auth_failed` | 令牌无效/吊销 | ❌ |
| `unsupported` | agent 不支持该动作 | ❌ |
| `not_found` | session/命令不存在 | ❌ |
| `conflict` | 会话忙/被外部修改 | ❌（可 force） |
| `rewrite_detected` | 源历史改写 | ✅（改 full） |
| `invalid_entry` / `invalid_bundle` | 数据非法 | ❌ |
| `too_large` | 批过大 | ✅（拆批） |
| `quota_exceeded` | 主机/会话超限 | ❌ |
| `timeout` / `network` | 超时/网络 | ✅ |
| `agent_error` | agent 主动报错 | 视情况 |

## 12. 安全、隐私与合规

### 12.1 威胁模型（摘要）

| 威胁 | 影响 | 缓解 |
|---|---|---|
| hub 被入侵 | 泄露镜像 + 可下发 | TLS、最小权限、可选静态加密、审计、令牌轮换；默认禁 `force` |
| daemon 令牌泄露 | 上传垃圾/下发消息 | 令牌按主机吊销；命令白名单；导入限定目录；审计 |
| 恶意 daemon | 污染镜像 | 命名空间隔离；entry 校验；单会话大小限制；不信任 `nativePath` |
| **console XSS** | 以用户身份操作 | Markdown 禁 raw HTML；CSP；工具输出纯文本；链接白名单 |
| CSRF | 借用户会话下发/导入 | SameSite Cookie + Origin 校验 + CSRF token（写接口） |
| 会话含密钥 | 泄露 | 源头脱敏、日志不落正文、保留期、删除权 |
| 中间人 | 窃听/篡改 | HTTPS/TLS + HSTS；可选证书指纹 pin |

### 12.2 凭据与传输

- 对外只暴露 443（或反代终止 TLS）；
- daemon token 存哈希（配置可写明文，启动后哈希）；console 密码推荐 Argon2id；
- 角色仅 `admin` / `viewer`，无 RBAC；配置文件 `0600`；
- console 会话 Cookie：`HttpOnly` + `Secure` + `SameSite=Lax`；
- 不复制任何上游模型 API Key 到 hub。

### 12.3 脱敏（daemon 侧，上传前）

默认规则（可覆盖/追加）：

```text
(?i)(api[_-]?key|token|secret|password)\s*[:=]\s*["']?[A-Za-z0-9_\-]{16,}
-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----[\s\S]+?-----END ...
(?i)authorization:\s*bearer\s+[A-Za-z0-9._\-]{20,}
(?i)(sk|pk|ghp|gho|github_pat|xox[baprs])_[A-Za-z0-9]{16,}
```

- 命中 → `[REDACTED:<kind>]`，并在 entry 上标 `redacted`；
- 只作用于上传副本，native 原文不动；
- console 展示命中统计，不展示原文；
- ⚠️ 正则脱敏必有漏；文档明确「hub 不是密钥保险箱」。

### 12.4 合规

- 随包第三方许可（pi/opencode/dsh）；
- 非官方声明（`pi-agent-hub` 为自研命名）；
- 数据驻留自托管；默认保留 30 天；
- 删除权：`DELETE /api/hub/hosts/:id?purge=1` 删除镜像与记录（审计保留 90 天）。

| `config/` | 加密备份 | 回灌 |
| 审计 | 追加日志 + 归档 | 只读保留 |

### 13.3 升级与迁移

- DB `schema_version` + 顺序迁移；启动自动迁移（先备份）；
- 存储格式（pi v3）不随版本变化；私有元数据只进 DB；
- pi SDK（读取）升级前跑 transcript 快照回归；可回滚依赖版本。

### 13.4 运维要点

| 场景 | 处置 |
|---|---|
| daemon 连不上 | 看 `last_seen`、日志、TLS/代理、令牌 |
| SSE 频繁断 | 反代缓冲/压缩/超时；`Last-Event-ID` 重放指标；缩短心跳 |
| 会话不更新 | 看 `lastTimestamp` 是否前进、manifest `status`、存档是否被轮转 |
| 大量 `rewrite_detected` | 该 agent 存档被改写/压缩迁移；必要时定时 full |
| 磁盘涨 | 调保留期、GC、pin、截断阈值；检查 FTS 索引大小 |
| console 打不开 | 静态资源版本/路径；`/healthz`；CSP 误伤看浏览器控制台 |
| 正文渲染异常 | 对比 `/raw` 原文；新增 entry 类型走 `unknown` 折叠 |
| 下发总冲突 | 检查两端同时操作；切 `managed-only` 或提高 `idleSeconds` |

### 14.5 技术选型评审

| 模块 | 选型 | 结论 | 需要补充/注意 |
|---|---|---|---|
| **hub-service** | Node 24 + **Express 5** + pi SDK | ✅ 可行 | 用 Express 5（async 错误）；补 `zod` + OpenAPI、`pino`、`helmet`、`express-rate-limit`、CSRF；SSE 单独关压缩/缓冲；**单实例**（SQLite + SSE），多副本需 Redis/Postgres 与 sticky；pi SDK 只读、版本锁定、不加载模型凭据 |
| **hub-console** | Vite + **Vue 3 + Element Plus** | ✅ 可行 | 用 `@tanstack/vue-query`、`@tanstack/vue-virtual`、`markdown-it` + DOMPurify、`shiki`、`diff2html`、`vue-i18n`；Element Plus 按需引入；大表格必须服务端分页 |
| **sync-daemon** | **Node 24** | ✅ 可行，但**形态要拆** | Win/macOS：用户级，由 Tauri 托盘守护（不注册服务）；Linux：node + pm2；`npx` 仅试用；单实例锁 |
| **sync-plugin-*** | **Node 子进程** + JSON-RPC/stdio | ✅ 可行 | 配置声明（参考 opencode.json）→ npm 解析/按需安装 → 子进程；`protocolVersion` + 监督 + 大包临时文件；allowlist/锁文件 |
| **sync-daemon-tray** | **Tauri v2 + 原生 HTML/CSS/JS**（Win/macOS） | ✅ 推荐 | 体积 ~5–15 MB + 内嵌 Node；托盘/菜单/自启/单实例；配置界面用静态 HTML（无前端框架/构建链）；仅构建期 Rust；CI 用 `tauri-action` |
| SQLite 驱动 | better-sqlite3 / node:sqlite **基准择优** | ✅ | 以 20M 条目写入、FTS5 搜索 P95、RSS 为指标；首版默认 better-sqlite3；V10 出结论后固定 |
| 构建发布 | npm + Tauri + 安装器 | ✅ | Windows NSIS/MSI、macOS dmg/pkg（签名/公证后续）、Linux npm + pm2；`tauri-action` 三平台矩阵 |

**主要修正点**

1. **托盘不是服务的一部分**（C-10）：daemon 做成无 GUI 服务；`sync-daemon-tray` 单独跑在用户会话，通过本地 API 控制；
2. **插件不放同进程**（C-9）：同进程 `import()` 的异常/内存泄漏会拖垮 daemon；子进程 + JSON-RPC 是更稳的边界；
3. **Express 的 SSE 要专门配置**（C-11）：`res.flushHeaders()`、关闭压缩/缓冲、心跳、反代读超时；
4. **hub 单实例**（C-8）：SSE 连接表与 SQLite 单写者决定了首版不能水平扩容；多副本是后续独立设计。

### 16.3 开放问题状态

> 原 Q1–Q11 已全部确认（详见 §3.12–§3.14）；**本期没有未决的产品问题**。后续新增问题在版本记录中追加。

| 主题 | 结论 |
|---|---|
| 多用户/认证 | 不做 RBAC；配置 `admin`/`viewer`；多个 daemon token；支持 YAML |
| 无人值守下发 | 桌面 `idle-only`、常驻 `managed-only`；`force` 仅 admin；配额 + 一键暂停 |
| 实时刷新 | 不需要流式；列表 10 s 轮询、正文手动刷新 |
| 保留期 | 30 天默认 + host/agent 覆盖 + pin；不导出 |
| 原生快照 | 同 kind 导入时 `export_native`，hub 临时中转、用后删除 |
| 跨 agent 导入 | 插件归一 + hub pi 内核；MVP 目标 pi |
| 多语言 | zh-CN + en（`vue-i18n`，跟随浏览器） |
| 导出/分享 | **都不做** |
| 读取/下发优先级 | 读取：存储 → API → ACP；下发：ACP → API |
| 插件签名 | 不强制（`requireSignedPlugins` 默认 false） |
| hub 多副本 | 只做单实例 |
| SQLite 驱动 | better-sqlite3 / node:sqlite 基准择优 |
| SSE 反代 | 只考虑 Nginx 简单代理 |
| 托盘签名/公证 | 暂缓 |
