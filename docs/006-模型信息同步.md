# 模型信息同步（`006-模型信息同步.md`）

> 本文档定义 **hub-console 经 hub-service、sync-daemon 获取某智能体（agent）在指定会话上下文下可用的
> 模型列表、思考深度（thinking level）枚举与当前生效的模型/思考深度** 的请求-应答链路（以下简称
> 「模型信息同步」或 Model Info Bridge）。
>
> 关联文档：协议总规范见 [`001-协议规范.md`](./001-协议规范.md)；异步轮询范式的工程目录同步见
> [`005-工程目录同步.md`](./005-工程目录同步.md)；本能力的消费方（会话底部聊天输入框）见
> [`007-下发聊天消息.md`](./007-下发聊天消息.md)。
>
> | 项 | 值 |
> |---|---|
> | 状态 | 设计稿（待实现） |
> | 通信模式 | **异步轮询**：console 发起 → hub 经 SSE 下发 → daemon 调插件 → REST 回传 → console 轮询取结果 |
> | 鉴权 | console 侧 Cookie+CSRF（仅 admin 可发起，GET 轮询不限角色）；daemon 侧 Bearer host token |
> | 能力边界 | 只读元数据；按 session 粒度发起；**不泄露** 模型凭据/私有字段；pi + opencode + dsh 全覆盖，daemon 统一调度、插件差异适配 |
> | 文档版本 | v0.1（2026-11-16） |

## 1. 背景与目标

### 1.1 问题

`007-下发聊天消息.md` 要在会话主区底部新增聊天输入框，其中「模型切换按钮」需要展示**该会话对应 agent
实际可用的模型**，「思考深度切换按钮」需要展示**该 agent 当前模型支持的思考深度枚举**。hub 本身不持有、
也不应持有各 agent 的模型目录与凭据（`000` §1：不做模型/推理托管，不保存 API Key）。

因此需要一条**按需、只读**的数据链路，让 console 实时向主机上的 agent 查询模型元数据，而不是在 hub 侧
静态配置模型清单（静态清单会与 agent 侧的 `models.json` / 项目 `enabledModels` / 当前会话作用域脱节）。

### 1.2 目标

新增一条由主机上的 **sync-daemon 调插件、插件调 agent 原生接口** 的查询链路，返回：

1. 该 agent 在该会话上下文（项目 cwd）下**可见的模型列表**（含每模型支持的思考深度）；
2. **当前生效的模型**（`provider` + `modelId`）；
3. **当前生效的思考深度**。

链路必须：

1. 复用 005 已验证的 **SSE 下发 + REST 回传 + console 轮询** 骨架，不引入新通信范式；
2. 天然容忍 daemon 离线/重连，无长连接超时坑；
3. **按 session 粒度**发起（模型作用域依赖项目 cwd），并按 `agentId + cwd` 做短 TTL 缓存，避免每次
   交互都拉起 agent 子进程；
4. 返回结构**最小投影**，绝不透传 `headers/baseUrl/cost/api/samplingParams/compat` 等可能含凭据或
   实现细节的字段。

### 1.3 非目标

- 不做模型 CRUD（不在 hub 增删改模型配置）；
- 不代理任何推理请求、不保存任何 API Key；
- 不在 hub 持久化模型清单（查询结果内存态机即可，缓存仅做性能优化，可随时失效）；
- 不实现「切换模型」本身——切换动作在 `007` 的下发链路中通过 `set_model` 完成，本文只负责「查询」。

## 2. 总体架构与数据链路

### 2.1 角色

| 角色 | 进程/位置 | 职责 |
|---|---|---|
| hub-console | 浏览器 SPA | 发起模型信息请求、轮询结果、渲染模型/思考深度选择器 |
| hub-service | 中心服务（Docker） | 鉴权、会话解析、SSE 下发、请求态机、结果暂存、脱敏兜底校验 |
| sync-daemon | 主机 Node 进程 | SSE 长连、按 agentId 路由到插件、REST 回传、结果缓存 |
| sync-plugin-* | Node 子进程 | 调 agent 原生接口（pi：`get_available_models`/`get_available_thinking_levels`/`get_state`），投影为最小 DTO |

### 2.2 时序（异步轮询）

```
hub-console                     hub-service                      sync-daemon(主机)          sync-plugin-pi-agent
    |  POST /api/hub/model-info-requests  |                            |                          |
    |  {sessionId}                        |                            |                          |
    |------------------------------------>|                            |                          |
    |  ① console 鉴权(admin+CSRF)          |                            |                          |
    |  ② 会话存在 → hostId/agentId/nativeId |                            |                          |
    |  ③ 建 requestId, state=dispatched    |                            |                          |
    |  ④ sse.send(hostId,"model_info_request",                          |                          |
    |        {requestId,agentId,nativeSessionId})                        |                          |
    |  ⑤ send 失败(离线)->503               |  SSE event: model_info_request                      |
    |<------------------------------------|--------------------------->|                          |
    |  202 {requestId,state:"dispatched"}  |  POST /api/v1/model-info-requests/:id/ack            |
    |                                      |<---------------------------|                          |
    |                                      |  state=accepted            |  JSON-RPC get_model_info  |
    |                                      |                            |------------------------->|
    |                                      |                            |   pi RPC(子进程)：       |
    |                                      |                            |   get_available_models   |
    |                                      |                            |   get_available_thinking_levels
    |                                      |                            |   get_state              |
    |                                      |  POST /api/v1/model-info-requests/:id/result         |
    |                                      |<---------------------------|                          |
    |  GET /api/hub/model-info-requests/:id |  state=completed|failed    |                          |
    |------------------------------------>|  结果内存暂存 5min           |                          |
    |  200 {state:"completed", result}      |                            |                          |
    |<------------------------------------|                            |                          |
    |  渲染模型/思考深度选择器               |                            |                          |
```

### 2.3 为什么沿用异步轮询

与 005 §2.3 同理：查询 `get_available_models` 需要 daemon 拉起 `pi --mode rpc --session <path>` 子进程，
模型目录加载可能耗时数秒；异步轮询不挂起 HTTP 连接，daemon 离线/慢都不占连接，状态可查询、可超时、可
失败收敛。前端 1s 轮询，交互上是「选择器 loading → 出列表」。

## 3. 协议与接口契约

> 沿用 `001-协议规范.md` 的双轨：console 走 `/api/hub/*`（Cookie+CSRF），daemon 走 `/api/v1/*`（Bearer token）。

### 3.1 console → hub：发起请求

```
POST /api/hub/model-info-requests
Content-Type: application/json
X-CSRF-Token: <csrf>
Cookie: hub_session=<session>

{ "sessionId": "hs_7f3k..." }
```

**响应（daemon 在线且已下发）：** `202 Accepted`
```json
{ "requestId": "mri_<uuid>", "state": "dispatched" }
```

**前置校验与错误：**

| 情况 | 状态码 | error.code |
|---|---|---|
| 非 admin 角色（viewer） | 403 | `forbidden_role` |
| CSRF 失败 | 403 | `csrf_failed` |
| `sessionId` 非字符串/为空 | 400 | `invalid_request` |
| 会话不存在 | 404 | `session_not_found` |
| 会话缺 `hostId/agentId/nativeId`（数据异常） | 422 | `session_incomplete` |
| 该 host 无对应 daemon token 配置 | 404 | `host_unknown` |
| 该 host 当前无 SSE 连接（`sse.send` 返回 false） | 503 | `host_offline` |

### 3.2 console → hub：轮询结果

```
GET /api/hub/model-info-requests/:requestId
```

| state | 含义 | HTTP 行为 |
|---|---|---|
| `dispatched` | 已下发，daemon 尚未 ack | 200 |
| `accepted` | daemon 已 ack，执行中 | 200 |
| `completed` | 成功，含 `result` | 200 |
| `failed` | 失败，含 `error` | 200（错误在体内，便于轮询统一处理） |
| `expired` | TTL 内未完成 | 200 |
| 未知/已清理的 requestId | — | 404 `not_found` |

**响应体：**
```json
{
  "requestId": "mri_…",
  "state": "completed",
  "result": { /* 见 §3.5 */ },
  "error": { "code": "…", "message": "…" }
}
```

### 3.3 hub → daemon：SSE 下发

新 SSE 事件 `model_info_request`（`SseHub.send(hostId, "model_info_request", payload)`）：
```json
{
  "requestId": "mri_…",
  "agentId": "a_…",
  "nativeSessionId": "019a…"
}
```
daemon 在 `handleEvent` 新增 `else if (event.event === "model_info_request")` 分支，与 deliver/import/
fs_request 并列。

### 3.4 daemon → hub：ack 与 result（Bearer 鉴权）

```
POST /api/v1/model-info-requests/:requestId/ack            -> 200 { ok: true }
POST /api/v1/model-info-requests/:requestId/result
{
  "ok": true,
  "result": { /* §3.5 */ }
}
// 或失败：
{
  "ok": false,
  "error": { "code": "agent_unsupported|agent_error|…", "message": "…" }
}
```
hub 按 `requestId` 定位内存中的请求记录（校验该 token 对应的 host 与请求归属一致，防跨 host 冒写）。

### 3.5 结果数据结构

```jsonc
{
  "agentId": "a_…",
  "models": [
    {
      "provider": "anthropic",
      "modelId": "claude-sonnet-4-5",
      "name": "Claude Sonnet 4.5",
      "reasoning": true,
      "input": ["text", "image"],
      "thinkingLevels": ["off", "minimal", "low", "medium", "high"]
    }
  ],
  "currentModel": { "provider": "anthropic", "modelId": "claude-sonnet-4-5" },
  "currentThinkingLevel": "high"
}
```

**字段语义（对应协议 DTO `ModelInfoResult` / `ModelInfoEntry`）：**

| 字段 | 来源（示例：pi） | 说明 |
|---|---|---|
| `models[].provider` | `Model.provider` | provider id，仅作分组/标识，不暴露显示名以外的敏感信息 |
| `models[].modelId` | `Model.id` | 模型 id |
| `models[].name` | `Model.name` | 展示名 |
| `models[].reasoning` | `Model.reasoning` | 是否支持思考 |
| `models[].input` | `Model.input` | 输入模态（`text`/`image`…），供前端判断是否显示图片按钮提示 |
| `models[].thinkingLevels` | 见「思考深度枚举」（pi：`getSupportedThinkingLevels`；dsh：`reasoning.efforts[].id`；opencode：reasoning 开/关） | 该模型支持的思考深度子集（字符串） |
| `currentModel` | `get_state().model` | 会话当前模型，可能为 `null` |
| `currentThinkingLevel` | `get_state().thinkingLevel` | 会话当前思考深度 |

**思考深度枚举（agent 特定，协议层用 `string[]` 承载）：**

- `models[].thinkingLevels` 与 `currentThinkingLevel` 都是**字符串**，由各插件按自身枚举投影：
  - pi：固定 7 档 `off|minimal|low|medium|high|xhigh|max`（协议常量 `THINKING_LEVELS` 供 pi 插件与测试参考）；
  - opencode：reasoning 开/关（⬜ 精确映射待验证）；
  - dsh：`ModelReasoning.efforts[].id`（每模型独立枚举，如 `low`/`medium`/`high` 或 provider 自定义 id）。
- hub **不做跨 agent 枚举校验**，只校验字符串非空；具体值由插件/agent 校验。

```ts
// 仅 pi 的固定档位；opencode/dsh 各有其 agent 特定字符串枚举。
export const THINKING_LEVELS = ["off", "minimal", "low", "medium", "high", "xhigh", "max"] as const;
```

### 3.6 插件 JSON-RPC：`get_model_info`

daemon 通过 `runtime.client.request("get_model_info", params)` 调用插件（沿用 `deliver`/`read_session`
的 RPC 形态）。`params`：
```jsonc
{ "instanceId": "pi-…", "nativeId": "019a…" }
```

插件实现约定（以 pi 为例）：

1. `findSessionPath(nativeId)` 定位会话文件（复用现有 `deliver` 逻辑）；
2. spawn `pi --mode rpc --session <sessionPath>`，`cwd = dirname(sessionPath)`，`PI_CODING_AGENT_DIR = agentDir`；
3. 顺序发送 `get_available_models`、`get_available_thinking_levels`、`get_state`（带 id 关联响应）；
4. 对每个 `Model` 用 `getSupportedThinkingLevels`（pi SDK）投影出 `thinkingLevels`；
5. **只投影** §3.5 的字段，其余一律丢弃；
6. 关闭 stdin 有序退出；超时（默认 30 s）SIGTERM/SIGKILL，返回 `agent_error`。

**多 agent 全覆盖（daemon 统一调度，插件差异适配）：**

`get_model_info` 是三插件同一份 JSON-RPC 契约；daemon 只负责路由与回传，差异收敛在插件内：

| kind | 模型列表来源 | 当前模型/思考深度来源 | 状态 |
|---|---|---|---|
| pi | RPC `get_available_models` | RPC `get_state` | ✅ 接口存在（`pi/packages/coding-agent/src/modes/rpc/rpc-mode.ts`） |
| opencode | HTTP `GET /api/model?types=chat`（可用模型快照） | 会话状态 / `GET /api/model/default`；无 pi 式 7 档思考深度，适配为 reasoning 开/关（⬜ 精确映射待验证） | ✅ API 存在（`opencode.ai/docs/api`） |
| dsh | Remote `session/modelCatalog`（`ModelCatalog`：provider 分组 + `default` + 每模型 `reasoning.efforts`） | `modelCatalog.default`（含 `reasoningEffort`）；会话级当前模型/思考深度 ⬜ 待确认 | ✅ 接口存在（`deepseek-harness/docs/subsystems/session.md`） |

> claude / codex 后续接入时按同一契约适配，本期不在范围。

**opencode 差异适配要点：**
- 模型引用为 `Model.Ref = { id, providerID, variant?, settings? }`：插件映射 `providerID → provider`、`id → modelId`，`name` 无独立显示名时取 `id`；
- opencode 无 pi 的 7 档思考深度，仅有 provider 级 `reasoningField` / `requireReasoning`：`get_model_info` 返回 `thinkingLevels` 时按「支持 reasoning → 归一到等价档位，否则 `["off"]`」处理（⬜ 待验证精确语义与档位映射）。

**dsh 差异适配要点：**
- 模型引用 `ModelCatalogModel { id, name, description?, reasoning?, badge? }` 分组在 `ModelProviderGroup { id, name, models[] }`：映射 `group.id → provider`、`model.id → modelId`、`model.name → name`；
- `input` 固定 `["text","image"]`（`session/prompt` 的 `PromptContentPart` 支持 text/image 块）；
- 思考深度 = `ModelReasoning.efforts[].id` → `thinkingLevels`；当前档位来自 `ModelSelection.reasoningEffort`；
- `currentModel`/`currentThinkingLevel` 优先取会话当前选择，无会话级端点时回退 `modelCatalog.default`（⬜ 待确认）。

- 任一插件对「模型列表」无能力时，返回 `models: []` 且 `ok:false, error.code="agent_unsupported"`；
  对「当前模型/思考深度」无能力时返回 `currentModel:null, currentThinkingLevel:null`；
- 返回结构始终是 §3.5 的同形 DTO，hub/console 不感知 agent 差异。

## 4. 数据脱敏与安全（核心）

模型元数据可能携带敏感字段，**插件投影是唯一允许的出口**。hub-service 收到 `result` 后再做一次**兜底
白名单校验**（防御性，防止插件实现越界透传）：

| 规则 | 说明 |
|---|---|
| `result` 顶层只允许 `agentId`/`models`/`currentModel`/`currentThinkingLevel` | 多余字段丢弃 |
| `models[]` 每项只允许 `provider/modelId/name/reasoning/input/thinkingLevels` | 其余丢弃 |
| `input[]`、`thinkingLevels[]` 必须是字符串数组 | 否则该请求置 `failed` |
| 明确禁止出现在结果中的字段 | `headers`、`baseUrl`、`api`、`cost`、`samplingParams`、`samplingParamsByThinkingLevel`、`compat`、`promptCache`、`maxTokens`、`contextWindow` 等 |

> `Model.baseUrl`/`headers` 在部分 provider 下可能承载鉴权头，属于**不得跨进程外泄**的数据。本设计不把
> 完整 `Model` 对象穿过 daemon/hub 边界，仅传最小投影。

## 5. hub-service 状态机与生命周期

### 5.1 状态机

```
            sse.send 成功                 ack 到达                 result(ok)
(创建) -----------------> dispatched ---------------> accepted -----------------> completed
   |                          |                        |   |
   | sse.send 失败            | TTL 60s 无 ack/result   |   | result(ok:false)
   v                          v                        v   v
503 host_offline（不建记录）  expired <-----------------  failed
```

- 状态枚举复用 `FsRequestState` 命名风格，新增专用集合：
  `dispatched | accepted | completed | failed | expired`；
- TTL：自建记录起 **60s** 未进入终态 → 惰性置 `expired`（轮询命中时判定，无需后台定时器）；
- 终态结果（completed/failed/expired）在内存保留 **5 分钟**供轮询，之后惰性删除；
- 纯内存 `Map<requestId, ModelInfoRequestRecord>`，hub 重启即失（查询类临时数据，可接受）。

### 5.2 记录结构（内存）

```ts
interface ModelInfoRequestRecord {
  requestId: string;
  hostId: string;            // 绑定 host，result 回传校验 token 归属
  agentId: string;
  sessionId: string;         // hub 会话 id（审计/排障）
  state: ModelInfoRequestState;
  createdAt: number;
  acceptedAt?: number;
  finishedAt?: number;
  result?: ModelInfoResult;
  error?: { code: string; message: string };
}
```

### 5.3 轮询节奏与前端超时

- console 轮询间隔 **1s**；
- 前端整体超时 **30s**（daemon 拉起 pi 子进程 + 模型目录加载可能耗时数秒）；超时停止轮询并提示；
- 组件卸载/切换会话时取消轮询（AbortController + 清 timer）。

## 6. 前端改造（hub-console）

### 6.1 API 客户端（`api.ts` 新增）

```ts
createModelInfoRequest(sessionId): Promise<{ requestId: string }>
pollModelInfoRequest(requestId): Promise<ModelInfoRequestRecord>
// 便捷方法：create + 轮询直到终态/超时，带 session 级缓存
getModelInfo(sessionId): Promise<ModelInfoResult>
```

### 6.2 选择器组件

- `ModelSelector.vue`（新）：复用 pi-web `ModelSelector` 的分组/筛选思路（`groupModelOptions` 按 provider
  分组、>8 项显示过滤框、当前模型高亮），用 Element Plus `el-popover`/`el-dropdown` + `el-input` 实现；
  - `options` 来自 `ModelInfoResult.models`；
  - `value` = `currentModel`；`onChange(provider, modelId)` 交给 composer（`007`）暂存；
  - 加载中显示 skeleton；`agent_unsupported` 显示「该智能体不支持模型切换」空态。
- `ThinkingLevelSelector.vue`（新）：下拉展示「跟随会话默认」+ 当前选中模型的 `thinkingLevels`；
  - `value` = `currentThinkingLevel`；`onChange(level | null)`（`null` 表示不下发 `set_thinking_level`）。

### 6.3 与会话选择器的衔接

左栏选中会话后，`TranscriptPane` 底部的 composer（`007`）在**首次需要**时（打开模型下拉或初始化）对
`selectedSession.id` 调 `getModelInfo(sessionId)`；`hostId/agentId/nativeId` 由 hub 从会话解析，前端无需手填。

### 6.4 缓存策略

- 前端按 `sessionId` 做 **30s TTL** 内存缓存；会话切换即失效；
- daemon 侧可选按 `agentId + cwd` 缓存 `get_model_info` 结果 **30–60s**（MAY），减少 pi 子进程拉起频率；
- 缓存只作性能优化，不改变正确性：任何请求都能强制刷新。

## 7. 鉴权与权限矩阵

| 动作 | console admin | console viewer | daemon（Bearer） |
|---|---|---|---|
| 发起 model-info-request（POST） | ✅ | ❌ 403 `forbidden_role` | — |
| 轮询 model-info-request（GET，只读） | ✅ | ✅（沿用 GET 不限制角色，但仅能查自己发起的 id） | — |
| SSE 接收 model_info_request | — | — | ✅（按 token 绑定 host） |
| ack/result 回传 | — | — | ✅（校验 host 归属） |

> 发起是 POST，严格沿用现有「非 GET 仅 admin + CSRF」中间件，不新增角色豁免。viewer 在 composer 中看到
> 选择器但不可发起（与 `007` 的下发权限一致）。

## 8. 错误码总表

| code | 产生方 | 含义 |
|---|---|---|
| `forbidden_role` / `csrf_failed` | hub | console 权限/CSRF |
| `invalid_request` | hub | 参数非法 |
| `session_not_found` | hub | 会话不存在 |
| `session_incomplete` | hub | 会话缺 hostId/agentId/nativeId |
| `host_unknown` | hub | hostId 无 daemon 配置 |
| `host_offline` | hub | 目标 host 无 SSE 连接，未下发 |
| `not_found` | hub | requestId 已清理 |
| `expired` | hub | 60s TTL 到期 |
| `agent_unsupported` | daemon/plugin | 该 agent kind 未实现模型查询 |
| `agent_error` | daemon/plugin | 插件执行/超时/子进程异常 |
| `invalid_result` | hub | result 兜底白名单校验失败 |

## 9. 兼容性与迁移

- **新增能力，不破坏既有接口**：仅新增 `model_info_request` SSE 事件与 4 个 model-info-requests 端点。
- 协议包 `@pi-agent-hub/protocol` 新增 `ModelInfoResult`/`ModelInfoEntry`/`ModelInfoRequestRecord`/
  `ModelInfoRequestEvent`/`THINKING_LEVELS` 等 DTO 与常量，不改既有类型字段。
- daemon 无需新增配置项；三插件（pi/opencode/dsh）按 §3.6 差异适配实现 `get_model_info`，未实现的 kind/能力由 daemon 归一为 `agent_unsupported` 或 `models:[]`。
- 无数据库 schema 变更（请求态纯内存）；无新增持久化。

## 10. 测试要点

### 10.1 单元（vitest）

- DTO 投影：完整 `Model` 对象 → `ModelInfoEntry` 仅保留白名单字段，`headers/baseUrl` 等被丢弃；
- hub 兜底校验：越界透传字段被剔除，非法数组类型置 `invalid_result`；
- 状态机：dispatched→accepted→completed/failed、TTL expired、终态 5min 清理、跨 host result 冒写拒绝；
- 前端 `groupModelOptions` 分组/筛选、`thinkingLevels` 缺失时选择器空态。

### 10.2 集成（Docker + 本机 daemon，Playwright）

- admin 打开某 pi 会话的模型下拉：加载后模型列表与 `pi --mode rpc get_available_models` 一致；
- 切换不同 cwd 的会话，模型列表随项目作用域变化（验证按 session 粒度）；
- viewer 发起被 403；daemon 离线发起即 503 无悬空记录；daemon 恢复后正常；
- opencode 会话返回 `GET /api/model` 的模型列表；dsh 会话返回 `session/modelCatalog` 的模型目录（provider 分组 + reasoning efforts）；选择器正确渲染，未实现 agent 显示空态而非崩溃。

### 10.3 回归

- 既有 fs_request/deliver/import/export SSE 链路不受新事件分支影响；全仓 `pnpm typecheck` 零新增错误。
