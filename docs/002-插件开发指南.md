# pi-agent-hub 插件开发指南（`002-插件开发指南.md`）

> 本文档面向 **sync-plugin-*** 的开发者：如何把一个新的异构 agent 接入 `sync-daemon`，
> 包括 npm 包结构、`piAgentHub` 元数据、JSON-RPC 协议、canonical 数据格式、配置/动态安装、
> 生命周期、安全与测试。
>
> 关联文档：
> - 总体与插件机制：[`000-工程规划.md`](./000-工程规划.md) §7.11
> - hub ↔ daemon 协议：[`001-协议规范.md`](./001-协议规范.md)
> - pi 会话格式：`../pi/packages/coding-agent/src/core/session-manager.ts`

| 项 | 值 |
|---|---|
| 插件协议版本 | **1.0**（`protocolVersion`） |
| 运行时 | **Node ≥ 22.19**（推荐 Node 24 LTS） |
| 传输 | 子进程 + JSON-RPC 2.0 over stdio（NDJSON） |
| 数据格式 | canonical = **pi session format v3** entries（不含 header） |
| 包命名 | `@pi-agent-hub/sync-plugin-<agent>` |
| 文档版本 | v0.3（2026-11-09） |

---

## 0. 插件模型

```text
sync-daemon（Node）
  ├─ 读取 ~/.pi-agent-hub/sync-daemon.json
  ├─ 解析 plugins[] → npm 包 / 本地路径
  ├─ spawn（每 agent 实例一个子进程）
  └─ JSON-RPC over stdio
        ▲
        │ session_changed（可选通知）
        ▼
sync-plugin-<agent>（Node 子进程）
  ├─ 读取该 agent 的 session 存档
  ├─ 归一为 canonical pi v3 entries
  └─ 调 agent 的 ACL/ACP/原生 API 执行 deliver/import
```

**边界**

| 责任 | daemon | 插件 |
|---|---|---|
| 发现/解析插件包 | ✅ | — |
| 读取 agent 存档 | — | ✅ |
| 归一/线性化 | — | ✅ |
| 脱敏 | ✅（上传前统一） | — |
| 同步到 hub（manifest/sync/SSE） | ✅ | — |
| 调用 agent 接口（下发/导入） | — | ✅ |
| 进程监督/重启/限内存 | ✅ | — |
| 配置 UI / 托盘 | daemon + tray | — |

**硬规则**

1. 插件**不得**在 daemon 进程内运行（必须子进程）；崩溃不能拖垮 daemon。
2. 插件**不得**直连 hub；只与 daemon 通过 stdio JSON-RPC 通信。
3. 插件**不得**修改 native 存档（除 `import_session` 新建）；`deliver` 必须走 agent 自己的接口。
4. 插件输出必须是 canonical pi v3 entries；**不含 session header**。

## 1. 包结构与元数据

### 1.1 命名

```text
@pi-agent-hub/sync-plugin-pi-agent      # pi
@pi-agent-hub/sync-plugin-opencode      # opencode
@pi-agent-hub/sync-plugin-dsh           # deepseek-harness
@pi-agent-hub/sync-plugin-claude        # 后续
@pi-agent-hub/sync-plugin-codex         # 后续
```

- 包名后缀 = `kind`（`pi-agent` 对应 `kind: "pi"`）；
- 一个包只声明一个 `kind`；同 kind 多实例由 daemon 配置区分。

### 1.2 `package.json` 必需字段

```jsonc
{
  "name": "@pi-agent-hub/sync-plugin-pi-agent",
  "version": "0.1.0",
  "type": "module",
  "engines": { "node": ">=22.19.0" },
  "bin": { "pi-agent-hub-sync-plugin-pi-agent": "dist/main.js" },
  "files": ["dist", "schema.json", "README.md"],
  "piAgentHub": {
    "kind": "pi",
    "protocolVersion": "1.0",
    "minDaemonVersion": "0.1.0",
    "capabilities": {
      "collect": true,
      "deliver": true,
      "import": true,
      "losslessImport": true,
      "exportNative": true,
      "controlInterface": "native-api"   // 有 ACP 则填 "acp"
    },
    "permissions": {
      "fsRead": ["~/.pi/agent/**"],
      "fsWrite": ["~/.pi/agent/sessions/**"],
      "net": ["127.0.0.1:*"],
      "spawn": ["pi"]
    },
    "timeouts": { "list": 30, "read": 120, "deliver": 600, "import": 1800 },
    "maxConcurrency": 2,
    "optionsSchema": "schema.json"
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `kind` | ✅ | `pi` / `opencode` / `dsh` / `claude` / `codex`；与配置/能力矩阵一致 |
| `protocolVersion` | ✅ | `1.0`；主版本不兼容时 daemon 拒绝加载 |
| `minDaemonVersion` | ✅ | 低于此版本 → `disabled` |
| `capabilities` | ✅ | `collect`/`deliver`/`import`/`losslessImport`/`exportNative`/`controlInterface`/`readStrategy`/`deliveryStrategy` |
| `permissions` | ✅ | 声明用途：`fsRead`/`fsWrite`/`net`/`spawn`；用于审计（首版不强制沙箱） |
| `timeouts` | 可选 | 秒；缺省用 daemon 默认值 |
| `maxConcurrency` | 可选 | 同时处理的请求数（默认 2） |
| `optionsSchema` | 可选 | JSON Schema，用于校验配置里的 `options` |

> `bin` 必须指向一个可执行 ESM 入口；插件由 `process.execPath`（Node）启动。

**接口优先级（Q9）**：

| 方向 | 优先级 |
|---|---|
| 读取（同步） | ① **直读存储格式**（版本适配，如 opencode V1/V2）→ ② agent API → ③ ACP |
| 下发（消息） | ① **ACP** → ② agent API |

插件内部实现优先级与降级；daemon/hub 不感知具体协议。`controlInterface` 声明实际使用的主接口。

### 1.3 构建与产物

- TypeScript + `tsup`/`tsc`，输出 ESM 到 `dist/`；
- 入口第一行读取 stdio，**stdout 只写协议**，日志写 stderr；
- `pnpm --filter @pi-agent-hub/sync-plugin-<kind> build`；
- 发布前 `npm pack --dry-run` 检查只包含 `dist/`、`schema.json`、README。

## 2. 配置、发现与动态安装

### 2.1 配置文件

`sync-daemon` 读取 **`~/.pi-agent-hub/sync-daemon.json`**（Windows：`%USERPROFILE%\.pi-agent-hub\sync-daemon.json`）。

```jsonc
{
  "plugins": [
    "@pi-agent-hub/sync-plugin-pi-agent",
    {
      "package": "@pi-agent-hub/sync-plugin-opencode@0.1.0",
      "options": { "server": "http://127.0.0.1:4096", "password": null }
    },
    "/absolute/path/to/local-plugin"
  ],
  "pluginInstall": true,
  "pluginAllowlist": ["@pi-agent-hub/*"],
  "pluginRoot": "~/.pi-agent-hub/plugins",
  "agents": {
    "pi": {
      "enabled": true,
      "instances": [{ "name": "default", "agentDir": "~/.pi/agent" }]
    },
    "opencode": {
      "enabled": true,
      "instances": [{ "name": "default", "dataDir": "~/.local/share/opencode" }]
    }
  }
}
```

- `plugins` 元素：字符串（包名，可带 `@version`）或 `{ package, options }`；
- `plugin` 作为 `plugins` 的别名（兼容 opencode 习惯）；
- `options` 原样传给插件的 `initialize.config.options`；
- `pluginAllowlist` 支持精确包名与 scope 通配（`@pi-agent-hub/*`）；
- daemon 的 `hub.token` 由 hub-service 的 `daemonTokens[]` 提供（每个 daemon 一个 token）；**插件不接触 token**。

### 2.2 解析顺序（daemon 侧）

```text
1. 绝对/相对路径 → 本地插件（不安装）
2. pluginRoot/node_modules
3. 安装包内置 node_modules（Tauri resources，只读）
4. npm root -g
5. 缺失且 pluginInstall=true 且命中 allowlist
   → 在 pluginRoot 执行 npm install（带锁文件）
6. 校验 package.json 的 piAgentHub 元数据
7. spawn 子进程 + initialize
```

**动态安装命令**（daemon 使用随包 npm，不依赖系统 npm）：

```bash
node <resources>/npm/bin/npm-cli.js install \
  --prefix ~/.pi-agent-hub/plugins \
  --save-exact --ignore-scripts --no-audit --no-fund \
  @pi-agent-hub/sync-plugin-opencode@0.1.0
```

- `pluginRoot` 首次使用时自动创建 `package.json` 与 `package-lock.json`；
- 安装失败/离线且缓存缺失 → `plugin_not_found`，console 与托盘配置界面显示；
- 版本升级：修改配置中的 `@version` 或显式 `npm update`；
- 配置热更新：daemon watch 文件 → 对比插件集合 → 安装/停止/重启对应子进程。

### 2.3 本地开发

```jsonc
{
  "plugins": ["/abs/packages/sync-plugin-pi-agent"],
  "pluginInstall": false
}
```

- 本地插件同样需要 `package.json` + `piAgentHub` + 已构建的 `dist/`；
- 修改后重启插件（配置保存或托盘「重载插件」）。

## 3. 进程与 JSON-RPC 协议

### 3.1 启动与 stdio

daemon 启动：

```ts
spawn(process.execPath, [bin], {
  stdio: ["pipe", "pipe", "pipe"],
  env: { ...process.env, PI_AGENT_HUB_PLUGIN: "1" },
});
```

- **stdin**：daemon → 插件的请求/通知；
- **stdout**：插件 → daemon 的响应/通知；**只允许 JSON-RPC**；
- **stderr**：日志（daemon 采集到 `sync-daemon.log`）。

### 3.2 帧格式

**NDJSON**：一行一个 JSON，`\n` 结尾：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}
```

- `id`：字符串/数字，插件必须原样回传；
- 通知无 `id`（如 `session_changed`）；
- 单行 ≤ 8 MiB；大负载走临时文件（§5.4）。

### 3.3 错误

```json
{"jsonrpc":"2.0","id":7,"error":{
  "code": -32000,
  "message": "session not found",
  "data": { "code": "not_found", "retryable": false }
}}
```

| `data.code` | 含义 | daemon 行为 |
|---|---|---|
| `invalid_request` | 参数错误 | 报错，不重试 |
| `unsupported` | agent 不支持该动作 | 置能力为 false/报错 |
| `not_found` | instance/session 不存在 | 报错 |
| `conflict` | 会话忙/被外部修改 | 下发失败，交给人 |
| `permission_denied` | 文件/接口无权限 | 报错 |
| `agent_error` | agent 返回错误 | 报错 |
| `timeout` | 插件内部超时 | daemon 可重试 |
| `internal` | 插件内部异常 | 报错 + 日志 |

### 3.4 握手

**request**

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
  "protocolVersion":"1.0",
  "daemonVersion":"0.1.0",
  "hostId":"h_...",
  "agentId":"a_...",
  "kind":"pi",
  "workDir":"/tmp/pi-agent-hub/plugin-...",
  "config": {
    "options": {},
    "instance": { "name":"default", "agentDir":"C:\\Users\\me\\.pi\\agent" }
  }
}}
```

**response**

```json
{"jsonrpc":"2.0","id":1,"result":{
  "pluginVersion":"0.1.0",
  "protocolVersion":"1.0",
  "capabilities":{
    "collect":true,"deliver":true,"import":true,
    "losslessImport":true,"exportNative":true,"controlInterface":"native-api"
  }
}}
```

规则：

- `protocolVersion` 主版本不同 → 插件返回 `unsupported` 并退出；
- `workDir` 是 daemon 提供的临时目录，插件只在这里写大文件；
- `config` 含用户 `options` 与实例配置；插件不得写回。

## 4. 方法契约

所有方法：params 为对象；result 为对象；超时由 daemon 强制。

### 4.1 `detect`

**params**：`{ "env"?: { "platform": "win32", "home": "..." } }`

**result**：

```json
{"instances":[{
  "instanceId":"pi-default",
  "displayName":"default",
  "homeDir":"C:\\Users\\me\\.pi\\agent",
  "version":"1.2.0"
}]}
```

- 多实例（不同 `agentDir`）返回多条；
- `instanceId` 在同一 plugin 内稳定（建议 `kind + "-" + hash(path)`）。

### 4.2 `list_sessions`

**params**：`{ "instanceId": "pi-default" }`

**result**：

```json
{"sessions":[{
  "nativeId":"019a...",
  "nativePath":"C:\\Users\\me\\.pi\\agent\\sessions\\--D--work-app--\\2026-...jsonl",
  "updatedAt":1762700000000,
  "title":"refactor auth",
  "cwd":"D:\\work\\app",
  "state":"idle",
  "entryCount":42
}]}
```

- 必须返回**所有可见历史会话**（含已结束）；
- `updatedAt` 用于 manifest 的 `skipped` 判定；
- `state`: `active` / `idle` / `missing`（**不代表删除**）。

### 4.3 `read_session`

**params**：

```json
{
  "instanceId":"pi-default",
  "nativeId":"019a...",
  "since":1762699500000,
  "lastEntryId":"ent_9",
  "workDir":"/tmp/..."
}
```

- `since` 缺省 = 全量；
- `since` 为**排他**下界：插件只返回 `timestamp > since` 的条目；
- 同毫秒：用 `lastEntryId` 在源存档中的位置跳过已同步条目；
- 无法保证顺序 → 返回 `mode:"full"`。

**result（内联）**

```json
{
  "mode":"delta",
  "entries":[ /* canonical pi v3 entries，按源顺序 */ ],
  "meta":{
    "cwd":"D:\\work\\app",
    "title":"refactor auth",
    "createdAt":1762600000000,
    "updatedAt":1762700000000,
    "state":"idle"
  }
}
```

**result（大包，推荐 > 2 MiB 或 > 1000 条）**

```json
{
  "mode":"full",
  "entriesPath":"/tmp/pi-agent-hub/plugin-.../sessions/019a.ndjson",
  "sha256":"hex",
  "count":12000,
  "meta":{ "cwd":"...", "title":"...", "createdAt":0, "updatedAt":0 }
}
```

- `entriesPath` 必须是 `workDir` 下的绝对路径；NDJSON，每行一个 entry；
- daemon 读取后删除临时文件；插件不得在响应后继续写该文件；
- `sha256` 对文件字节计算；`count` 为条目数。

### 4.4 `watch`（可选）

**params**：`{ "instanceId": "pi-default" }`
**result**：`{ "watching": true }`

之后可发送通知：

```json
{"jsonrpc":"2.0","method":"session_changed","params":{
  "instanceId":"pi-default","nativeId":"019a...","updatedAt":1762700000000
}}
```

- 没有 `watch` 能力时，daemon 按 `pollSeconds` 轮询；
- 通知可能合并/丢失，daemon 仍以 manifest 为准。

### 4.5 `deliver`

**params**：

```json
{
  "deliveryId":"dlv_...",
  "instanceId":"pi-default",
  "nativeId":"019a...",
  "message":"继续把测试补上",
  "images":[{"mime":"image/png","dataBase64":"..."}],
  "policy":"idle-only",
  "force":false
}
```

**result**：

```json
{"ok":true,"state":"completed","nativeMessageId":"msg_...","warnings":[]}
```

- `state`：`accepted` / `running` / `completed`（daemon 会 ack + result）；
- 会话被外部改动/忙 → `conflict`（不得硬写）；
- 必须按 `deliveryId` 幂等：重复请求不得重复 prompt；
- 图片可能以 base64 内联；超过 8 MiB 的图片由 daemon 拒绝。

### 4.6 `import_session`

**params**：

```json
{
  "importId":"imp_...",
  "instanceId":"pi-default",
  "bundlePath":"/tmp/pi-agent-hub/bundles/blb_.../bundle.json",
  "targetCwd":"D:\\work\\app"
}
```

**result**：

```json
{"nativeId":"019c...","nativePath":"...","warnings":["provider/model 未迁移"]}
```

- 必须**新建**会话，不得覆盖已有；
- 目标 id 已存在 → `conflict`；
- 目标目录不在允许根 → `permission_denied`；
- bundle 可能带 `native` 引用（同 kind 的 `export_native` 结果）：优先用原生导入，缺失时用 canonical；
- 原生快照导入后不得回传/长期保存。

### 4.7 `export_native`

**params**：

```json
{
  "instanceId": "pi-default",
  "nativeId": "019a...",
  "format": "pi-jsonl-v3",
  "workDir": "/tmp/..."
}
```

**result**：

```json
{
  "nativePath": "/tmp/pi-agent-hub/plugin-.../native/019a.jsonl",
  "format": "pi-jsonl-v3",
  "sha256": "hex",
  "bytes": 102400
}
```

- 仅同 kind 导入使用；由 hub 的 `export_native` 命令触发；
- 必须输出**原生存档**（pi 原始 JSONL / opencode export / …），不是 canonical；
- `nativePath` 必须在 `workDir` 下；daemon 上传后删除；
- **不做脱敏**（原生快照需在目标侧使用；hub 只临时中转，TTL 1 h）；
- 不支持时返回 `unsupported`；
- 权限：仅 admin 发起；审计。

### 4.8 `ping` / `shutdown`

- `ping` → `{ "pong": true, "uptimeMs": 12345 }`；
- `shutdown` → `{}`，随后插件退出；daemon 在超时后 kill。

## 5. canonical 数据契约

### 5.1 基本要求

- **pi session format v3** 的 entry（11 类）；
- **不含 session header**（hub 依据 `meta` 生成）；
- 每条必须有 `id`、`type`、`timestamp`、`parentId`；
- 首条 `parentId = null`，其后 `parentId` = 前一条 `id`（单链）；
- `timestamp` 为 ISO 8601 字符串，单调不减；
- 同一会话内 `id` 唯一；跨同步稳定。

### 5.2 11 类 entry

`message` / `model_change` / `thinking_level_change` / `usage` / `compaction` /
`branch_summary` / `custom` / `custom_message` / `context_edit` / `label` / `session_info`。

> `custom` 不进入 LLM 上下文；可用于来源/标记，但不要伪造用户消息。

### 5.3 消息映射（参考）

| 原生 | canonical |
|---|---|
| user 文本/图片 | `{type:"message", message:{role:"user", content, timestamp}}` |
| assistant 文本/思考/工具调用 | `{type:"message", message:{role:"assistant", content:[...], api, provider, model, usage, stopReason, timestamp}}` |
| 工具结果 | `{type:"message", message:{role:"toolResult", ...}}` |
| shell 执行 | `{type:"message", message:{role:"bashExecution", command, output, exitCode, ...}}` |
| 压缩摘要 | `{type:"compaction", summary, firstKeptEntryId, tokensBefore, ...}` |
| 分支摘要 | `{type:"branch_summary", fromId, summary, ...}` |
| 模型切换 | `{type:"model_change", provider, modelId}` |
| 用量 | `{type:"usage", kind, provider, model, usage}` |

> 字段细节以 pi `session-manager.ts` 的类型为准；跨 agent 无法映射的元数据可省略/降级，
> 但不要写入错误类型。

### 5.4 分支/子 agent

- 只输出**主分支**；被丢弃分支不要混入；
- 需要在 `meta`/`custom` 中记录 `droppedBranches` 可选；
- 子 agent 会话如可独立读取，可作为独立 native session 上报。

### 5.5 大文件规则

- 阈值建议：> 1000 条或 > 2 MiB 使用 `entriesPath`；
- 文件必须是 NDJSON、UTF-8、每行一个 JSON；
- 写完后 fsync；返回前计算 sha256；
- 不得把 header 写进文件。

## 6. 生命周期与监督

```text
discover → validate manifest → spawn → initialize → ready
   ↑                                              │
   └──── restart（退避） ← exit/crash/timeout ←───┘
```

| 项 | daemon 行为 |
|---|---|
| 握手 | `initialize` 超时 10 s；失败 → 重试 2 次 → `disabled` |
| 健康 | `ping` 每 30 s；连续 2 次失败 → 重启 |
| 超时 | 按 `piAgentHub.timeouts`；超时 kill 子进程 |
| 崩溃 | 1s→60s 指数退避；10 min 内最多 5 次；超过 → `disabled` |
| 空闲 | 5 min 无请求 → 回收；下次按需拉起 |
| 配置变更 | 新增/删除/版本变化 → 安装/停止/重建；不影响其它插件 |
| 状态 | `starting` / `ready` / `degraded` / `disabled` / `error`，console 与托盘可见 |

插件应：

- 收到 `shutdown` 后释放资源并退出（≤ 5 s）；
- 不假设 daemon 会长期存活；每次 `initialize` 重新探测；
- 不把状态只放内存（daemon 重启后要能恢复）。

## 7. 安全

- 插件以 daemon 同一用户运行；**不得**要求 root/管理员；
- `permissions` 是声明式的，daemon 首版用于审计；可选 Node Permission Model：
  `--experimental-permission --allow-fs-read=... --allow-fs-write=... --allow-child-process`
  （注意插件需要 spawn agent/loopback 网络，需逐项放行；默认关闭）；
- `npm install --ignore-scripts`；插件优先纯 JS，不在用户机编译原生模块；
- `pluginAllowlist` 默认只允许 `@pi-agent-hub/*`；第三方需显式加入；
- `npm audit signatures` / npm provenance；可选 `requireSignedPlugins`；
- 插件不得监听公网端口；`net` 仅 loopback；
- 日志不得输出 token/消息正文/存档原文；stderr 会进 daemon 日志；
- 导入只写 `import.allowedRoots`；`deliver` 不得直接改存档。

## 10. 参考实现

### 10.1 pi（`sync-plugin-pi-agent`）

| 项 | 做法 |
|---|---|
| 存档 | `<agentDir>/sessions/<project-dir>/<ts>_<id>.jsonl` |
| 清单 | 扫描 `sessions/*/*.jsonl`；`updatedAt` 取文件 mtime/最后 entry |
| 读取 | 按行读 JSONL；跳过 header；按 `timestamp > since` 过滤；尾部半行留待下次 |
| 归一 | 原生即 canonical；补 `id`（若缺）+ 线性化 |
| 下发 | `pi --mode rpc --session <path>` → `get_state` → `prompt` → `agent_settled` → 关闭 stdin |
| 导入 | 新 id + 复制 entries + 重写 header + 尾部 `custom` 来源条目 |
| 原生导出 | 直接复制原始 JSONL（含 header）到 `workDir`，计算 sha256 |
| 依赖 | 可只用 Node 标准库；如需 v1/v2 升级可依赖 `@earendil-works/pi-coding-agent` |

### 10.2 opencode（`sync-plugin-opencode`）

| 项 | 做法 |
|---|---|
| 存档 | **直读 SQLite 优先**：V2 `session_v2` / `session_message` / `session_part`；V1 兼容；不可读回退 `opencode serve` |
| 归一 | message + parts（text/reasoning/tool/file）→ canonical |
| 下发 | **ACP 优先**（`opencode acp`）→ `session.prompt` |
| 导入 | `session.export` / `session.import` |
| 原生导出 | `session.export` |
| 原生导出 | `session.export` 输出 JSON 到 `workDir` |
| options | `{ "server": "http://127.0.0.1:4096", "password": "..." }` |
| 注意 | 消息可编辑/重生成 → 发现历史变化时返回 `mode:"full"` |

### 10.3 dsh（`sync-plugin-dsh`）

| 项 | 做法 |
|---|---|
| 存档 | **直读 `.jsonl`（zstd 解码）优先**；不可读回退 dsh host `/api` |
| 归一 | 事件 → canonical（⬜ 字段以真实会话为准） |
| 下发 | 优先 ACP（若有）→ ⬜ 待确认 `/api` 方法 |
| 导入 | 本期 `unsupported` |
| 原生导出 | 用 host `session.export`（⬜ 格式确认） |
| 注意 | root 编码（zstd/none）不可混用 |

## 11. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `plugin_not_found` | 未安装/allowlist 不匹配 | 检查 `plugins`、`pluginRoot`、网络/registry |
| `plugin_invalid` | 缺 `piAgentHub`/`bin` | 检查 package.json |
| `protocol_mismatch` | 主版本不一致 | 升级插件或 daemon |
| `plugin_timeout` | 单次请求超时 | 调大 `timeouts`、检查存档/网络 |
| 崩溃循环 `disabled` | 插件异常 | 看 `sync-daemon.log` stderr；用 fixture 复现 |
| 会话列表为空 | 路径/权限/编码 | 检查 agentDir、权限、zstd |
| 增量重复/漏 | `since`/同毫秒处理错误 | 用 `lastEntryId`；必要时 `mode:"full"` |
| Windows 启动失败 | `npm.cmd`/路径空格 | 用 `process.execPath` + 绝对路径；不要 shell |
| 大包失败 | `entriesPath` 不在 `workDir` | 写到 daemon 指定目录并校验 sha256 |

## 附录 B — 最小插件骨架

```ts
#!/usr/bin/env node
import { createInterface } from "node:readline";

const rl = createInterface({ input: process.stdin, crlfDelay: Infinity });

function send(msg: unknown) {
  process.stdout.write(JSON.stringify(msg) + "\n");
}

const handlers: Record<string, (params: Record<string, unknown>) => Promise<unknown> | unknown> = {
  initialize: (p) => ({
    pluginVersion: "0.1.0",
    protocolVersion: "1.0",
    capabilities: { collect: true, deliver: true, import: false, losslessImport: false, exportNative: false, controlInterface: "native-api" },
  }),
  ping: () => ({ pong: true }),
  list_sessions: () => ({ sessions: [] }),
  read_session: () => ({ mode: "full", entries: [], meta: { cwd: "", title: "", createdAt: 0, updatedAt: 0 } }),
  deliver: () => ({ ok: true, state: "completed" }),
  export_native: () => { throw Object.assign(new Error("unsupported"), { code: "unsupported" }); },
  import_session: () => { throw Object.assign(new Error("unsupported"), { code: "unsupported" }); },
  shutdown: () => ({}),
};

rl.on("line", async (line) => {
  type Request = {
    jsonrpc?: string;
    id?: string | number;
    method?: string;
    params?: Record<string, unknown>;
  };
  let req: Request;
  try { req = JSON.parse(line) as Request; } catch { return; }
  if (!req.method) return;
  const fn = handlers[req.method];
  if (!fn) {
    send({ jsonrpc: "2.0", id: req.id, error: { code: -32601, message: "method not found" } });
    return;
  }
  try {
    const result = await fn(req.params ?? {});
    if (req.id !== undefined) send({ jsonrpc: "2.0", id: req.id, result });
  } catch (error) {
    const e = error as Error & { code?: string };
    send({ jsonrpc: "2.0", id: req.id, error: {
      code: -32000, message: e.message,
      data: { code: e.code ?? "internal", retryable: false },
    }});
  }
});
```
