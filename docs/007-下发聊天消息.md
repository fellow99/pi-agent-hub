# 下发聊天消息（`007-下发聊天消息.md`）

> 本文档定义 **hub-console 在会话主区底部通过聊天输入框（composer）向指定主机、指定智能体、指定会话下发
> 一条聊天提示词（文本 + 图片 + 可选模型/思考深度）** 的完整链路（以下简称「聊天下发」或 Chat Deliver）。
> 它是既有 `deliver` 能力（`000` §4.4/§7.5、`001` §5.3/§7.8）的**增强与 UI 落地**。
>
> 关联文档：协议总规范见 [`001-协议规范.md`](./001-协议规范.md)；模型/思考深度枚举的来源见
> [`006-模型信息同步.md`](./006-模型信息同步.md)；异步轮询范式见 [`005-工程目录同步.md`](./005-工程目录同步.md)。
>
> | 项 | 值 |
> |---|---|
> | 状态 | 设计稿（待实现） |
> | 通信模式 | **同步发起 + 异步执行**：console POST 下发 → hub 经 SSE `deliver` → daemon 调 agent → REST ack/result → console 轮询/刷新 |
> | 鉴权 | console 侧 Cookie+CSRF（仅 admin 可下发，viewer 只读）；daemon 侧 Bearer host token |
> | 能力边界 | 一条消息一次下发；图片内联上传、hub 中转；模型/思考深度可选（不下发 = 跟随会话当前） |
> | 文档版本 | v0.1（2026-11-16） |

## 1. 背景与目标

### 1.1 对既有「下发一条聊天提示词」需求的 review

既有设计已具备正确的主体框架，保留不推翻：

| 既有设计 | 位置 | 结论 |
|---|---|---|
| SSE `deliver` 事件 + REST ack/result | `001` §5.3/§5.5 | ✅ 保留 |
| `deliveryId` 业务幂等键 + `attempt` 重投 | `001` §5.6 | ✅ 保留 |
| 每会话串行（C-1 单写者） | `000` §7.5、`001` §5.6 | ✅ 保留 |
| `idle-only / managed-only / force` 策略 | `000` Q2、`001` §5.3 | 🔶 收敛：首版仅 `idle-only`(默认) + `force`(admin)，`managed-only` 后置 |
| daemon 调插件 `deliver` → pi RPC `prompt` | `000` §7.5 | ✅ 保留 |

**差距（本次补齐）：**

1. **无会话内输入框**：`000` §6.5 仍写「下发是独立弹窗」，console 主区没有 composer；本次在
   `TranscriptPane` 底部新增，参考 pi-web `ChatInput`；
2. **图片链路未接通**：协议有 `images`，但 console→hub→daemon→plugin 全链路未实现；
3. **无模型/思考深度选择**：`deliver` 载荷无 `model`/`thinkingLevel`；需依赖 `006` 的模型信息同步；
4. **delivery 态机/持久化是脚手架**：hub 侧仅内存 `Map`，无 DB、无重投、无 TTL、无落库审计、无发送后
   状态回显；
5. **会话串行/冲突检查未实现**：需在 daemon 侧对同一 native session 的并发 deliver 串行化，并在冲突时
   回 `conflict`（不重试）。

### 1.2 目标

在 hub-console 会话主区底部提供一个与 pi-web 对齐的聊天输入框，支持：

- 输入文本并发送；
- 上传图片（多张，缩略图预览、可移除、拖拽可选）；
- 切换模型（选项来自 `006` 的模型信息同步）；
- 切换思考深度（枚举来自 `006`，且随所选模型过滤）；
- 显示发送后状态（排队 → 已下发 → 已接受 → 完成/失败），完成后刷新正文看到新消息。

### 1.3 非目标

- 不做**流式**渲染（hub 是只读镜像 + 受控下发，不代理推理流；完成后经一次同步回显完整消息）；
- 不做模型/思考深度之外的 agent 配置管理；
- 不做多级审批/队列调度 UI（`force` 仅 admin + 二次确认，沿用既有策略）；
- 不改变 viewer 只读语义（viewer 不提供有效下发入口）。

## 2. 总体架构与数据链路

### 2.1 角色

| 角色 | 进程/位置 | 职责 |
|---|---|---|
| hub-console | 浏览器 SPA | composer（文本/图片/模型/思考深度/策略）、提交下发、轮询状态、刷新正文 |
| hub-service | 中心服务（Docker） | 鉴权、参数校验、图片落盘、SSE 下发、delivery 态机/持久化、图片下载端点 |
| sync-daemon | 主机 Node 进程 | SSE 长连、幂等/冲突检查、下载图片、按 agentId 路由、REST 回执 |
| sync-plugin-* | Node 子进程 | 调 agent 原生接口执行 `set_model`/`set_thinking_level`/`prompt` |

### 2.2 时序

```
hub-console          hub-service                    sync-daemon               sync-plugin-pi-cli / agent
    | POST /api/hub/deliveries                        |                           |
    | {sessionId,text,images,model,thinkingLevel,policy,idempotencyKey}        |
    |----------------------------------------------->|                           |
    | ① admin+CSRF；会话解析 host/agent/native        |                           |
    | ② 校验文本/图片/模型/思考深度/策略                |                           |
    | ③ 图片 base64 落盘(dataDir/deliveries/<id>/images/)                      |
    | ④ 建 delivery 记录(state=queued)                 |                           |
    | ⑤ sse.send(hostId,"deliver",{…images:[{mime,url,sha256,bytes}]})         |
    |   send 失败 → state=queued 等待重投（或 503）     |  SSE event: deliver       |
    |<-----------------------------------------------|------------------------->|
    | 202 {deliveryId,state:"dispatched"|"queued"}    |  幂等检查(本地已完成表)      |
    |                                                 |  同 session 串行锁          |
    |                                                 |  POST /api/v1/deliveries/:id/ack
    |                                                 |<-------------------------|
    |                                                 |  GET /api/v1/deliveries/:id/images/:index (Bearer, 逐张)
    |                                                 |  下载到临时文件             |
    |                                                 |  JSON-RPC deliver {model,thinkingLevel,images:[{mime,path}]}
    |                                                 |-------------------------->|
    |                                                 |   pi RPC：                |
    |                                                 |   get_state → set_model? → set_thinking_level? → prompt
    |                                                 |   等 agent_settled        |
    |                                                 |  POST /api/v1/deliveries/:id/result
    |                                                 |<-------------------------|
    | GET /api/hub/deliveries/:id（1s 轮询）            |  state=completed|failed    |
    |----------------------------------------------->|                           |
    | completed → 触发/等待同步 → 重新拉 transcript 尾部 |                           |
```

### 2.3 与既有 deliver 的关系

- **保留**：SSE `deliver` 事件名、`/api/v1/deliveries/:id/ack|result`、`deliveryId` 幂等、`attempt` 重投
  （ack 60s 超时、result 10min 超时、最多 5 次）、同 session 串行；
- **扩展**：`deliver` 事件与 `DeliverRequest` 增加 `model`、`thinkingLevel`、`images`（图片由 hub 中转，
  事件内仅给 `url`）；console 侧由「独立弹窗」改为「底部 composer」。

## 3. 协议与接口契约

### 3.1 console → hub：发起下发

```
POST /api/hub/deliveries
Content-Type: application/json
X-CSRF-Token: <csrf>
Cookie: hub_session=<session>
Idempotency-Key: <optional>

{
  "sessionId": "hs_7f3k...",
  "text": "继续把测试补上",
  "images": [
    { "mime": "image/png", "dataBase64": "…", "name": "screenshot.png" }
  ],
  "model": { "provider": "anthropic", "modelId": "claude-sonnet-4-5" },
  "thinkingLevel": "high",
  "policy": "idle-only",
  "force": false,
  "idempotencyKey": "…"
}
```

**字段约定：**

| 字段 | 必填 | 约束 |
|---|---|---|
| `sessionId` | ✅ | 会话存在，解析出 host/agent/native |
| `text` | 条件 | 字符串；`text` 与 `images` **至少一项非空**（支持纯图片消息） |
| `images[]` | 否 | 见 §3.2 图片约束 |
| `model` | 否 | `{provider:string, modelId:string}`；不传/`null` = 不改模型，跟随会话当前 |
| `thinkingLevel` | 否 | 字符串；值须来自该会话 `006` 返回的所选模型 `thinkingLevels`（agent 特定）；不传/`null` = 不改 |
| `policy` | 否 | `idle-only`(默认) \| `force` |
| `force` | 否 | 仅 admin；`force` 需二次确认（前端） |
| `idempotencyKey` | 否 | ≤128 字符，透传幂等（`001` §1.4） |

**响应：** `202 Accepted`
```json
{ "deliveryId": "dlv_<uuid>", "state": "dispatched" }
// host 离线仍建记录排队：{ "deliveryId": "dlv_…", "state": "queued" }
```

**前置校验与错误：**

| 情况 | 状态码 | error.code |
|---|---|---|
| 非 admin 角色（viewer） | 403 | `forbidden_role` |
| CSRF 失败 | 403 | `csrf_failed` |
| 参数非法（sessionId/text/images/model/thinkingLevel/policy） | 400 | `invalid_request` |
| `text` 与 `images` 均为空 | 400 | `invalid_request` |
| `thinkingLevel` 非字符串或空串 | 400 | `invalid_request` |
| 图片超限/类型不支持 | 400 | `image_invalid` / `image_too_large` |
| 会话不存在 | 404 | `session_not_found` |
| 会话缺 `hostId/agentId/nativeId`（数据异常） | 422 | `session_incomplete` |
| `force` 但角色不足 | 403 | `forbidden_role` |
| 该 host 无对应 daemon token 配置 | 404 | `host_unknown` |

### 3.2 图片上传与下载

**console → hub（内联 base64）：**
- mime 白名单：`image/png`、`image/jpeg`、`image/gif`、`image/webp`、`image/bmp`（与 pi-web 对齐）；
- 单张解码后 ≤ **10 MB**；单次 ≤ **10 张**（对齐 pi-web `MAX_ATTACHED_IMAGE_BYTES` / `MAX_ATTACHED_IMAGES`）；
- 最坏情况 10×10MB base64 ≈ 133MB，hub 需将 `express.json` body limit 提升至 **≥160MB**（或在总量上做二次校验兜底）；
- 不重编码、不压缩（pi 侧 `prompt` 自行处理缩放，参考 pi-web `readImageFile`）。

**hub 落盘：** `dataDir/deliveries/<deliveryId>/images/<index>`，计算 `sha256` 与 `bytes`；SSE 事件只带：
```json
"images": [ { "mime": "image/png", "url": "/api/v1/deliveries/dlv_…/images/0",
              "sha256": "hex", "bytes": 84213 } ]
```

**daemon 下载：**
```
GET /api/v1/deliveries/:deliveryId/images/:index
Authorization: Bearer phk_...
```
- 校验 token 对应 host == delivery 归属 host；`Content-Type` 取存储的 mime；`Cache-Control: no-store`；
- 支持 `Range`（复用静态文件能力）；URL 有效期与 delivery 生命周期一致（终态/GC 后 410 `image_expired`）；
- daemon 下载后写临时文件，插件侧 `DeliverRequest.images` 传 `{ mime, path }`（避免 JSON-RPC 大 base64）。

### 3.3 hub → daemon：SSE `deliver`（扩展后）

```jsonc
{
  "deliveryId": "dlv_…",
  "agentId": "a_…",
  "nativeSessionId": "019a…",
  "hubSessionId": "hs_…",
  "message": "继续把测试补上",
  "images": [ { "mime": "image/png", "url": "/api/v1/deliveries/dlv_…/images/0",
                "sha256": "hex", "bytes": 84213 } ],
  "model": { "provider": "anthropic", "modelId": "claude-sonnet-4-5" },
  "thinkingLevel": "high",
  "policy": "idle-only",
  "force": false,
  "attempt": 1,
  "createdAt": 1762700000000,
  "expiresAt": 1762700600000
}
```

### 3.4 daemon → hub：ack 与 result（Bearer 鉴权）

沿用 `001` §5.5，不新增端点：

```
POST /api/v1/deliveries/{deliveryId}/ack     -> 200 { ok: true }
POST /api/v1/deliveries/{deliveryId}/result
{ "ok": true,  "result": { "state": "completed", "nativeMessageId": "msg_…", "warnings": [] } }
// 或
{ "ok": false, "error": { "code": "conflict|agent_error|model_not_found|…", "message": "…", "retryable": false } }
```

### 3.5 插件 JSON-RPC：`deliver`（扩展后）

```ts
export interface DeliverRequest {
  deliveryId: string;
  instanceId: string;
  nativeId: string;
  message: string;
  images?: Array<{ mime: string; dataBase64?: string; path?: string }>;
  model?: { provider: string; modelId: string } | null;
  thinkingLevel?: string | null;
  policy?: "idle-only" | "force";
  force?: boolean;
}
```

## 4. 模型与思考深度的应用

### 4.1 pi 插件执行时序（`promptPiSession` 扩展）

```
spawn pi --mode rpc --session <nativePath>（cwd = dirname(path)，PI_CODING_AGENT_DIR = agentDir）
  → get_state                          # 校验 sessionFile 一致，读 current model/thinkingLevel
  → model 指定且 != 当前               # set_model {provider, modelId}
  → thinkingLevel 指定且 != 当前        # set_thinking_level {level}
  → prompt { message, images? }         # images 为 ImageContent[]：{type:"image", data: base64, mimeType}
  → 等 agent_settled（或 agent_end + 空闲阈值）
  → 有序退出；超时 SIGTERM/SIGKILL
```

**要点：**
- `set_model` 失败（模型不存在/不在当前作用域）→ 回 `model_not_found`，**不发送** `prompt`；
- `set_thinking_level` 只接受 `THINKING_LEVELS` 枚举值；pi 内部对越界/模型不支持的档位做 clamp
  （`getSupportedThinkingLevels`），插件透传即可；
- 图片由插件从 `path` 读文件 → base64 → `ImageContent`（`pi-ai` 契约：`data` 为 base64 字符串）；
- 模型/思考深度的切换会由 pi 会话自身记录为 `model_change`/`thinking_level_change` entry，随下一次同步
  出现在 hub 镜像（`000` §6.2 映射为 `meta` 时间线标签）。

### 4.2 多 agent 全覆盖：daemon 统一调度，插件差异适配

daemon 是**统一调度层**（agent 无关）：路由、同 session 串行、幂等、图片下载、ack/result 都只依赖
`DeliverRequest` 契约，不感知具体 agent。差异收敛在 `sync-plugin-*`：每个插件把同一 `deliver` 契约映射到
各自 agent 的原生调用。

| kind | `deliver` 适配（文本/图片/模型/思考深度） | 差异与降级 |
|---|---|---|
| pi | RPC：`get_state` → `set_model?` → `set_thinking_level?` → `prompt` | 完整支持；模型不存在回 `model_not_found` |
| opencode | ACP 优先（`opencode acp`），否则 HTTP `POST /api/session/{id}/prompt`（`000` §8.2、`opencode.ai/docs/api`） | 文本/图片走 `PromptInput` 文本块 + 文件附件（base64+mime）；模型用 `Model.Ref` 或先 `POST /api/session/{id}/model`；无 pi 式思考深度，`thinkingLevel` 适配为 reasoning 开/关（⬜ 精确映射待验证） |
| dsh | Remote `session/prompt`（`SessionPromptRequest { requestId, sessionId, mode: queue\|steer, content: PromptContentPart[] }`） | 文本→`{type:text,text}`；图片→`{type:image,mediaType,data(base64),name?}`；模型/思考深度先 `session/selectModel`（`ModelSelection{provider,model,reasoningEffort?}`）再 prompt；`mode` 默认 `queue` |

> claude / codex 后续接入时按同一 `DeliverRequest` 契约适配，本期不在范围。

**通用原则：**
- `deliver` 契约为三插件同一份；daemon 不做任何 agent 特判；
- 某能力（如思考深度）目标 agent 不支持时，插件**忽略该字段**并在 `result.warnings` 标注，而非让整条
  下发失败；只有基础能力（文本）失败才回 `ok:false`；
- 图片统一由 daemon 下载为临时文件，插件以 `images:[{mime,path}]` 接收，避免各 agent 图片编码差异外泄。

### 4.3 思考深度枚举的唯一来源

- 枚举**不跨 agent 统一**：composer 的下拉**只显示** `006` 返回的所选模型的 `thinkingLevels`（agent 特定字符串）
  + 顶部「跟随会话默认」（映射为不传 `thinkingLevel`）；
- `THINKING_LEVELS`（`off|minimal|low|medium|high|xhigh|max`）只是 **pi** 的固定档位，定义在
  `@pi-agent-hub/protocol` 供 pi 插件与测试参考；opencode 为 reasoning 开/关，dsh 为
  `ModelReasoning.efforts[].id`（每模型独立）；
- hub 只校验 `thinkingLevel` 为非空字符串，具体值由插件/agent 校验（pi clamp、dsh 回
  `model-unavailable` 等）；不接受 pi-web 的 `"auto"`（= 不传该字段）。

## 5. hub-service delivery 状态机与持久化

### 5.1 状态机（复用 `DeliveryState`）

```
(创建) ── sse.send 成功 ──► dispatched ── ack 到达 ──► accepted ── result(ok) ──► completed
   |                           |                          |   |
   | sse.send 失败             | ack 60s 超时(attempt++)    |   | result(ok:false)
   v                           v                          v   v
 queued（TTL 24h 重投）      expired（attempt>5）         running?  failed
                                                          （可选 progress 事件）
```

- `queued`：host 离线时建记录排队；SSE 重连/`reset` 后经 pending 补齐重投（`001` §5.5）；
- `canceled`：`POST /api/hub/deliveries/:id/cancel`（仅未 dispatched 生效）；
- 终态（completed/failed/expired/canceled）保留展示，GC 按 retentionDays。

### 5.2 DB schema 扩展（`deliveries` 表）

在 `000` §5.6 草案基础上补齐字段：

```sql
deliveries(
  id TEXT PK,
  host_id TEXT, agent_id TEXT, session_id TEXT, native_session_id TEXT,
  text TEXT,
  images_json TEXT,             -- [{mime,url,sha256,bytes}]
  model_provider TEXT, model_id TEXT,
  thinking_level TEXT,
  policy TEXT, force INTEGER,
  state TEXT, attempts INTEGER,
  created_at INTEGER, dispatched_at INTEGER, accepted_at INTEGER, settled_at INTEGER,
  native_message_id TEXT, error TEXT,
  idempotency_key TEXT UNIQUE
)
```

### 5.3 同 session 串行与冲突（C-1 单写者）

- hub 侧：同一 `session_id` 的 `deliver`/`import` 进入 per-session 串行队列（`000` §5.6/`001` §5.6）；
- daemon 侧：同一 native session 的 deliver 本地串行锁；执行前做空闲检查（pi：文件 mtime / `get_state`），
  非空闲且非 `force` → 回 `conflict`（`retryable:false`，不重试）；
- 幂等：daemon 本地保存已完成 deliveryId（建议 7 天），重复事件直接回原 result。

### 5.4 发送后的正文回显

- daemon 在 `result` 前触发该会话一次同步（manifest 单项 → 差分 → `POST /sync`，沿用 `000` §7.5）；
- console 收到 `completed` 后重新拉 `transcript` 尾部（`GET /api/hub/sessions/:id/transcript?tail=…`），
  新 user message / 后续 assistant 回复随同步出现。

## 6. 前端改造（hub-console）

### 6.1 组件：`ChatComposer.vue`（新，参考 pi-web `ChatInput.tsx`）

位置：`TranscriptPane.vue` 模板底部、滚动区之外（sticky/fixed 于主区底部）。props：

{ session: SessionSummary | null }

**布局（参考 pi-web）：**

**行为：**

| 模型按钮 | `ModelSelector`（`006` §6.2）；显示当前模型名；未加载/`agent_unsupported` 显示禁用态 |
| 思考深度按钮 | `ThinkingLevelSelector`（`006` §6.2）；显示当前档位；选项随模型过滤 |
| 策略 | 溢出菜单：`idle-only`(默认) / `force`；`force` 需 `el-message-box` 二次确认（仅 admin） |
| 发送 | 先校验 session 非空、有文本或图片、主机在线（可发但提示排队）；`POST /api/hub/deliveries` |
| 发送后 | 1s 轮询 `GET /api/hub/deliveries/:id` 至终态；期间显示状态；完成后清空输入、刷新 transcript 尾部 |
| 权限 | viewer：渲染 composer 但输入/按钮/发送禁用，显示「只读账号无法下发」；未选会话：整体禁用 |

### 6.3 与正文/选择器的衔接

- `Viewer.vue` 将 `selectedSession` 传给 `TranscriptPane` → `ChatComposer`；
- 选中会话切换时：清空 composer 草稿、清空图片、重置模型/思考深度选择（待 `006` 重新拉取）；
- 发送完成后：复用 `TranscriptPane` 现有 `loadTail()` 重新拉取最新消息。

## 8. 错误码总表

| code | 产生方 | 含义 |
|---|---|---|
| `forbidden_role` / `csrf_failed` | hub | console 权限/CSRF |
| `invalid_request` | hub | 参数非法（含空消息、非法 thinkingLevel） |
| `image_invalid` / `image_too_large` | hub | 图片 mime 不支持 / 超限 |
| `session_not_found` | hub | 会话不存在 |
| `host_unknown` | hub | hostId 无 daemon 配置 |
| `not_found` | hub/daemon | deliveryId 不存在 / 图片 index 越界 |
| `conflict` | daemon | 会话被外部改动/非空闲（不重试） |
| `model_not_found` | plugin | `set_model` 找不到目标模型 |
| `unsupported` | daemon/plugin | 目标 agent 不支持图片/模型/思考深度 |
| `agent_error` | daemon/plugin | 子进程/执行异常 |
| `expired` | hub | ack/result 超时 |
| `image_expired` | hub | 交付终态/GC 后图片不可下载 |

## 9. 兼容性与迁移

- **不破坏既有接口**：`POST /api/hub/deliveries`、`/api/v1/deliveries/:id/ack|result` 路径不变，仅
  **新增可选字段**（`model`/`thinkingLevel`/`images`），老客户端不带即等于旧行为；
- 协议包 `@pi-agent-hub/protocol` 扩展 `DeliverRequest`、`DeliverEvent`、`DeliveryRecord`（`thinkingLevel`
  为 agent 特定 `string`），并新增 `THINKING_LEVELS`（pi 固定档位，仅作参考）；不改既有字段；
- hub 新增图片落盘目录 `dataDir/deliveries/*`，随 delivery GC 清理；无破坏性 schema 变更（`deliveries`
  表新增列，旧库可迁移）；
- daemon 无需新增配置；插件按需实现 `model`/`thinkingLevel`/`images`，不支持时回 `unsupported`。

## 10. 测试要点

### 10.1 单元（vitest）

- 参数校验：空文本+空图片拒绝；空/非字符串 `thinkingLevel` 拒绝（agent 侧拒绝非法档位并回 error）；图片 mime/size/count 限制；
- delivery 态机：queued→dispatched→accepted→completed/failed、ack/result 超时、attempt 上限、cancel；
- 同 session 串行与 `conflict` 不重试；deliveryId 幂等；
- pi 插件：`set_model` 找不到 → `model_not_found` 且不发 `prompt`；`set_thinking_level` clamp 透传；
  `ImageContent` base64 编码正确。

### 10.2 集成（Docker + 本机 daemon，Playwright）

- admin 在会话底部输入文本发送：状态 排队→下发→接受→完成，完成后正文尾部出现新 user message；
- 上传 2 张图片发送：daemon 能下载图片、pi 收到 `images` 并完成；超限/非图片被 400；
- 切换模型 + 思考深度发送：会话镜像出现 `model_change`/`thinking_level_change` meta 标签；
- viewer 禁用发送；daemon 离线发送进入 queued，恢复后自动重投；`force` 二次确认生效。

### 10.3 回归

- 既有 fs_request/model_info/import/export 不受影响；只读查看、搜索、右栏功能不变；全仓 `pnpm typecheck`
  零新增错误。
