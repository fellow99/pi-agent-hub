# pi-agent-hub 协议规范（`001-协议规范.md`）

> 本文档定义 **hub-service ↔ sync-daemon** 的同步/下发协议，以及 **hub-service ↔ hub-console** 的读取/控制
> 契约。目标是：任何语言实现的 daemon 只要遵守本文，就能汇总会话、接收下发、执行导入。
>
> 关联文档：工程总体与存储/渲染见 [`000-工程规划.md`](./000-工程规划.md)；适配器插件机制见 000 §7.11。

| 项 | 值 |
|---|---|
| 协议版本 | **v1**（URL 前缀 `/api/v1`） |
| 传输 | HTTPS/TLS；上行 REST（JSON）；下行 **SSE** |
| 编码 | UTF-8；时间戳为 UTC 毫秒（entry 内为 pi 原生 ISO 字符串） |
| 契约类型 | canonical = **pi session format v3** entries（见 000 §5.4） |
| 文档版本 | v0.2（2026-11-09） |

---

## 0. 范围与术语

### 0.1 范围

| 方向 | 内容 | 章节 |
|---|---|---|
| daemon → hub | 认证、版本探测、manifest、session 同步、删除、回执 | §2–§4 |
| hub → daemon | SSE 下发 `deliver` / `import` / `reset` | §5 |
| daemon → hub | 下发 ack/result、导入 result、bundle 下载 | §5.6、§6 |
| console → hub | 会话查看（列表/正文/搜索）与控制面 | §7 |
| 不在本文 | daemon ↔ plugin 的 JSON-RPC（插件为 Node 子进程，见 000 §7.11）、UI 视觉细节 | — |

### 0.2 术语

| 术语 | 含义 |
|---|---|
| **host** | 一台机器，由 daemon 代表；`hostId` 由 token 配置映射 |
| **agent** | agent 实例（`pi`/`opencode`/`dsh`/…）；`agentId` 在 host 内唯一 |
| **nativeId** | agent 自己的会话 id（不透明字符串） |
| **hubSessionId** | hub 分配的会话 id，格式 `hs_` + 26 位小写 base32 |
| **canonical entry** | pi v3 session entry（JSON 对象，含 `id/type/timestamp/parentId`） |
| **since** | 同步水位：daemon 只发送 `timestamp > since` 的 entry |
| **lastTimestamp** | hub 已存的最后一条 entry 的 UTC 毫秒；`null` = 需要完整同步 |
| **lastEntryId** | 同毫秒 tie-breaker，hub 已存的最后一条 entry id |
| **deliver** | 向某 native session 发一条消息并触发执行 |
| **import** | 在目标 agent 上新建会话（一次性） |

### 0.3 一致性关键词

`MUST` / `MUST NOT` / `SHOULD` / `MAY` 按 RFC 2119 解释。

## 1. 通用约定

### 1.1 传输与安全

- 所有 daemon API `MUST` 走 HTTPS（TLS 1.2+）；仅开发模式允许 `http://127.0.0.1`。
- `Authorization: Bearer <token>`；令牌按 host 绑定，不可跨主机使用。
- 请求/响应 `Content-Type: application/json; charset=utf-8`（SSE 除外）。
- 反向代理 `MUST` 对 SSE 关闭响应缓冲与压缩：`X-Accel-Buffering: no`、`proxy_buffering off`、读超时 ≥ 60 s。

### 1.2 编码规则

- JSON 必须 UTF-8；`NaN`/`Infinity` 禁止；数字为 IEEE-754 安全整数范围。
- **时间戳**：
  - API 层（manifest、水位、状态、SSE）统一为 **UTC 毫秒整数**；
  - canonical entry 内部保留 pi 原生 `timestamp`（ISO 8601 字符串），hub 解析为毫秒计算水位。
- **ID**：`hostId` = `h_` + 26 位 base32；`agentId` = `a_` + 26 位；`hubSessionId` = `hs_` + 26 位；
  `deliveryId`/`importId`/`uploadId`/`requestId` = 前缀 + ULID/UUIDv7 字符串。对端 MUST 把 ID 当不透明串。
- **entry 链**：同一会话内 entry `id` 唯一；`parentId` 必须构成单链（首条为 `null`）。

### 1.3 统一错误响应

```jsonc
{
  "error": {
    "code": "rewrite_detected",        // 稳定枚举，见 §8
    "message": "entry ent_7 content differs from stored copy",
    "retryable": true,
    "details": { "entryId": "ent_7" }  // 可选
  },
  "requestId": "req_01J..."            // 服务端回填，用于排障
}
```

- HTTP 状态与 `code` 同时使用；客户端 MUST 同时判断两者。
- `5xx` 且 `retryable=true` 才重试；`4xx` 默认不重试（`409 rewrite_detected` 例外，改 full）。

### 1.4 幂等

- 写接口接受 `Idempotency-Key` 请求头（或 body 同名字段），长度 ≤ 128；
- hub 保存 `(hostId, key)` → 响应摘要 **24 h**；
- 同 key 同 body：返回原响应；同 key 不同 body：`409 idempotency_conflict`；
- 未带 key 的写请求按「至少一次 + 业务去重」处理（entryId / deliveryId / importId）。

### 1.5 分页与游标

- 列表类接口使用 `limit`（默认 50，最大 500）+ `cursor`（不透明串）；
- 响应返回 `nextCursor`（无更多时为 `null`）；
- `cursor` MUST NOT 暴露内部偏移，服务端可用 `(sortKey, id)` 编码。

### 1.6 压缩与大负载

- 内联条目使用 `entriesGz`：`base64(gzip(JSON 数组))`；单请求体 ≤ 16 MiB（解压后 ≤ 64 MiB）。
- 大负载（完整会话 / 大批量 / 原生快照）使用 **upload 流**（§4.5）：
  - `PUT /api/v1/uploads/{uploadId}`，`Content-Type: application/x-ndjson`，`Content-Encoding: gzip`；
  - 每行一个 canonical entry；服务端流式校验并落临时文件；`Digest: sha-256=...` 校验完整性。
- 服务端 MUST 限制 gzip 解压比（防 zip bomb）与单行大小（8 MiB）。

### 1.7 时间与偏差

- daemon 与 hub 的时钟偏差超过 **5 min** 时，hub 可拒绝同步并返回 `409 clock_skew`（可配置关闭）。
- 所有 TTL/租约/重试以 **hub 服务端时间**为准；daemon 不得用本地时间判定过期。

### 1.8 版本

- `GET /api/v1/meta` → `{ apiVersion: 1, minDaemonVersion, capabilities, limits }`。
- 不兼容时：`426 api_version_unsupported`，body 带 `minDaemonVersion`。
- 破坏性变更 → `/api/v2`；同版本内只允许新增可选字段。

## 2. 鉴权与认证

### 2.1 角色与凭据

| 角色 | 凭据 | 用途 |
|---|---|---|
| daemon | **预配置 token**（`hub-service.json` 的 `daemonTokens[]`） | 所有 `/api/v1/*` |
| console 用户 | **用户名 + 密码** → HttpOnly Cookie + CSRF token | `/api/hub/*` |
| 运维脚本 | Personal token（可选） | `/api/hub/*` |

### 2.2 Token 与用户配置

**不再有配对/注册流程**；token 与用户均写在 hub-service 配置中。

```jsonc
// ~/.pi-agent-hub/hub-service.json（也支持 hub-service.yml）
{
  "users": [
    { "username": "admin", "passwordHash": "argon2id$...", "role": "admin" },
    { "username": "alice", "password": "dev-only", "role": "viewer" }
  ],
  "daemonTokens": [
    { "name": "laptop-win", "token": "phk_...", "hostName": "laptop-win" },
    { "name": "mac-mini", "tokenHash": "sha256:...", "hostName": "mac-mini" }
  ]
}
```

- 每个 daemon 配置自己的 `hub.token`；**不同 daemon MUST 用不同 token**；
- hub 以 token 绑定 host（`hostName` → host 记录）；未知/禁用 → `401 token_unknown`；
- 用户角色仅 `admin` / `viewer`；`viewer` 只读；
- 轮换：修改配置 + 重启或 `POST /api/hub/reload`（admin）；daemon 更新 token；
- 无注册/配对 endpoint；无用户 CRUD API。

### 2.3 daemon 请求头

```http
Authorization: Bearer phk_...
X-Daemon-Version: 0.1.0
X-Request-Id: req_01J...
Idempotency-Key: ...            # 写接口可选
```

`hostId` 由 token 绑定，**请求体不得传**；服务端忽略任何客户端提供的 hostId。

### 2.4 console 登录与 CSRF

- `POST /api/hub/auth/login { username, password }` → `Set-Cookie: hub_session=...; HttpOnly; Secure; SameSite=Lax`；
- 响应体返回 `csrfToken`；写接口（POST/PATCH/DELETE）MUST 带 `X-CSRF-Token`；
- 服务端同时校验 `Origin`/`Referer` 与 Cookie；
- `POST /api/hub/auth/logout` 清除会话；
- 角色从配置读取（`admin` / `viewer`），不在 token/session 中自行声明。

## 3. 数据模型

### 3.1 host 与 agent

```jsonc
// host（只读，console 展示）
{ "id": "h_...", "name": "laptop-win", "os": "windows", "arch": "x86_64",
  "daemonVersion": "0.1.0", "labels": ["dev"], "status": "online",
  "lastSeenAt": 1762700000000, "createdAt": 1762600000000 }

// agent instance
{ "id": "a_...", "hostId": "h_...", "kind": "pi", "displayName": "default",
  "version": "1.2.0", "homeDir": "C:\\Users\\me\\.pi\\agent",
  "capabilities": { "collect": true, "deliver": true, "import": true },
  "status": "online" }
```

### 3.2 session 元数据

```jsonc
{
  "hostId": "h_...",
  "agentId": "a_...",
  "nativeId": "019a...",              // agent 自己的 id，不透明
  "nativePath": "C:\\Users\\me\\.pi\\agent\\sessions\\...jsonl",  // 可选，仅排障
  "cwd": "D:\\work\\app",
  "title": "refactor auth",
  "createdAt": 1762600000000,
  "updatedAt": 1762700000000,         // agent 侧更新时间
  "state": "active"                   // active|idle|missing
}
```

`state:"missing"` 仅表示本地存档暂不可读，**不代表删除**；删除必须调用 §4.4。

### 3.3 canonical entry

- 结构：**pi session format v3** 的 entry（`type` ∈ 11 类，含 `id/parentId/timestamp/type`）。
- 同步请求中的 `entries` **不含 session header**；hub 依据 `session` 元数据生成 header。
- 链约束：首条 `parentId = null`，其后每条 `parentId` = 前一条 `id`（线性化由 daemon 负责）。
- `id`：同一会话内唯一；若原生 id 缺失/重复，daemon MUST 生成稳定 id（建议 `sha256(nativeId + ordinal)[0..24]`），
  并在同一会话的多次同步中保持一致。
- `timestamp`：ISO 8601 字符串（pi 原生），daemon MUST 保证单调不减（不可保证时用 `mode=full`）。
- 单条 entry ≤ 8 MiB（序列化后）。

### 3.4 transcript 块（读取 API 用）

`hub-service` 把 entries 规范化为块（数据契约，渲染见 000 §6.2）：

```ts
type TranscriptItem = {
  seq: number; entryId: string; type: string; ts: number;
  role?: "user" | "assistant" | "tool" | "system" | "meta";
  blocks: Block[];
};

type Block =
  | { kind: "text"; text: string; markdown?: boolean }
  | { kind: "thinking"; text: string }
  | { kind: "toolCall"; callId: string; name: string; input: unknown; status: "pending" | "ok" | "error" }
  | { kind: "toolResult"; callId?: string; name: string; ok: boolean;
      preview: string; bytes: number; truncated: boolean; rawUrl?: string }
  | { kind: "image"; mime: string; url: string; width?: number; height?: number }
  | { kind: "bash"; command: string; output: string; exitCode?: number; cancelled?: boolean }
  | { kind: "summary"; summaryType: "compaction" | "branch"; text: string; tokensBefore?: number }
  | { kind: "diff"; files: Array<{ path: string; patch: string }> }
  | { kind: "meta"; label: string; detail?: string; level?: "info" | "warn" }
  | { kind: "unknown"; raw: string };
```

### 3.5 状态枚举

| 对象 | 状态 |
|---|---|
| session | `active` / `idle` / `missing` / `error` / `deleted` |
| delivery | `queued` / `dispatched` / `accepted` / `running` / `completed` / `failed` / `expired` / `canceled` |
| import | `queued` / `preparing` / `transferring` / `materializing` / `completed` / `failed` |
| upload | `open` / `committed` / `expired` / `failed` |

## 4. 同步 API（daemon → hub）

### 4.1 版本探测

`GET /api/v1/meta`

```jsonc
{
  "apiVersion": 1,
  "minDaemonVersion": "0.1.0",
  "serverTime": 1762700001000,
  "capabilities": { "sse": true, "uploads": true, "compression": "gzip" },
  "limits": {
    "manifestSessionsPerRequest": 5000,
    "syncEntriesPerRequest": 5000,
    "maxInlineBytes": 16777216,
    "maxUploadBytes": 134217728,
    "maxEntryBytes": 8388608,
    "maxSessionBytes": 33554432
  }
}
```

### 4.2 `POST /api/v1/sync/manifest`

**请求**

```jsonc
{
  "requestId": "req_01J...",
  "agents": [
    {
      "agentId": "a_...",
      "kind": "pi",
      "version": "1.2.0",
      "sessions": [
        { "nativeId": "019a...", "updatedAt": 1762700000000,
          "title": "refactor auth", "cwd": "D:\\work\\app", "state": "idle" }
      ]
    }
  ]
}
```

- 单请求最多 `manifestSessionsPerRequest` 个 session；超过时 daemon 分片发送（同一 `agentId` 可多片）。
- `agentId` 由 daemon 稳定派生：`a_` + base32(hash(hostId + "\0" + kind + "\0" + homeDir))；
  同一实例重启后不变；
- 不存在的 `agentId` 由 hub 自动登记（以本次 `kind/version` 为准）；已存在则更新 `version`；
- `capabilities` 可选上报（`collect/deliver/import`），用于 console 展示与动作前置校验。

**响应**

```jsonc
{
  "serverTime": 1762700001000,
  "sessions": [
    { "agentId": "a_...", "nativeId": "019a...", "hubSessionId": "hs_7f3k...",
      "lastTimestamp": 1762699500000, "lastEntryId": "ent_9",
      "status": "ok", "entryCount": 42 },
    { "agentId": "a_...", "nativeId": "019b...", "hubSessionId": "hs_2m9q...",
      "lastTimestamp": null, "lastEntryId": null,
      "status": "new" }
  ]
}
```

| `status` | 含义 | daemon 动作 |
|---|---|---|
| `new` | hub 无此会话 | `lastTimestamp=null`，完整同步 |
| `ok` | 已有水位 | 同步 `> lastTimestamp` 的条目 |
| `skipped` | hub 记录的 `updatedAt` 与本次相同 | 可跳过（仍返回水位便于调试） |
| `full` | 被要求完整重同步（resync/改写后） | `lastTimestamp=null`，按 full 同步 |
| `quota` | 主机/会话超配额 | 停止该会话同步并告警 |
| `error` | hub 侧索引异常 | 按 `5xx` 退避 |

**幂等**：同一 `(hostId, agentId, nativeId)` 重复提交只更新元数据，不产生新会话。

### 4.3 `POST /api/v1/sync/sessions/{hubSessionId}`

**请求（内联增量）**

```jsonc
{
  "requestId": "req_01J...",
  "agentId": "a_...",
  "nativeId": "019a...",
  "since": 1762699500000,          // delta 必填；full 可省略
  "mode": "delta",                  // delta | full
  "session": {
    "cwd": "D:\\work\\app",
    "title": "refactor auth",
    "createdAt": 1762600000000,
    "updatedAt": 1762700000000,
    "state": "active"
  },
  "entries": [ /* canonical entries，按源顺序 */ ],
  "truncated": false
}
```

**大负载**：把 `entries` 换成 upload 引用（§4.5）：

```jsonc
{ "mode": "full", "session": { ... }, "entriesRef": { "uploadId": "upl_..." } }
```

**响应**

```jsonc
{
  "hubSessionId": "hs_7f3k...",
  "merged": 12,
  "skipped": 0,
  "lastTimestamp": 1762700000000,
  "lastEntryId": "ent_21",
  "entryCount": 54,
  "status": "ok"
}
```

**合并规则**

1. **校验**（整批原子）：entry 结构、id 唯一、链完整、单条 ≤ `maxEntryBytes`、总解压 ≤ 限制；
   任一条失败 → `422 invalid_entry`（不落盘）。
2. `mode=delta`：
   - 允许 `timestamp >= since`；`timestamp < since` → `422 entry_before_since`；
   - 已存在同 `entryId` 且内容摘要相同 → 计入 `skipped`；
   - 同 `entryId` 但内容摘要不同 → `409 rewrite_detected`（不落盘，要求 full）；
   - 其余按顺序追加，`parentId` 必须等于当前 leaf（否则 `422 invalid_chain`）。
3. `mode=full`：
   - 忽略 `since`；用本次 entries 重建单链，写临时文件 → `rename`；
   - 重复提交同一内容（同 `entriesRef`/相同摘要）→ 幂等返回。
4. 成功后在响应中返回新的 `lastTimestamp` / `lastEntryId` / `entryCount`。
5. 服务端 MUST 在单一事务/写锁内完成「校验 + 落盘 + 水位更新」。
6. 脱敏规则变更会导致同 `entryId` 的内容摘要变化；这属于合法重写，hub 返回 `409 rewrite_detected`，
   daemon 对该会话改发 `mode=full`。

**时间戳**：`since` 为排他下界（daemon 选择 `>`）；同毫秒由 daemon 用 `lastEntryId` 在源存档中的位置
决定起点，hub 只校验 `>= since`，并按 `entryId` 去重。

### 4.4 `POST /api/v1/sync/sessions/{hubSessionId}/deleted`

```jsonc
{ "nativeId": "019a...", "deletedAt": 1762700000000 }
```

- 标记墓碑（`state=deleted`），保留索引 30 天；重复调用幂等；
- 后续 manifest 若再次出现该 `nativeId`，按**新会话**处理（新 hubSessionId）。

### 4.5 大负载 upload

**① 创建 upload**

`POST /api/v1/uploads`

```jsonc
{
  "kind": "session-entries",        // 或 "native-snapshot"
  "hubSessionId": "hs_7f3k...",
  "mode": "full",                     // full | delta
  "since": 1762699500000,             // delta 时必填
  "encoding": "ndjson+gzip",
  "totalEntries": 12000,              // 可选
  "sha256": "hex"                     // 可选，提交时校验
}

// 201
{ "uploadId": "upl_...", "putUrl": "/api/v1/uploads/upl_...",
  "expiresAt": 1762701800000, "maxBytes": 134217728 }
```

**② 上传**

```http
PUT /api/v1/uploads/{uploadId}
Authorization: Bearer phk_...
Content-Type: application/x-ndjson
Content-Encoding: gzip
Digest: sha-256=<base64>

<gzip 压缩的 NDJSON，每行一个 canonical entry>
```

- 流式写入临时文件；超过 `maxBytes` → `413 upload_too_large`；
- 校验失败 → `422 invalid_entry`，upload 置 `failed`；
- 重复 PUT 允许（覆盖临时文件，直到 commit）。

**③ 提交同步**

`POST /api/v1/sync/sessions/{hubSessionId}`，body 使用 `entriesRef:{uploadId}`（见 §4.3），
hub 在同一写锁内完成校验/落盘，然后删除临时文件。

**④ 过期**：`expiresAt` 未 commit 的 upload 由 GC 删除；commit 后上传内容不可重放。

### 4.6 限流与配额

| 范围 | 默认 | 超限 |
|---|---|---|
| `manifest` | 30 req/min/host | `429` + `Retry-After` |
| `sync/sessions` | 120 req/min/host | 同上 |
| `uploads` PUT | 并发 2/host | 同上 |
| 单主机存储 | 2 GiB | `409 quota_exceeded`（manifest 返回 `status:"quota"`） |
| 单会话 | 32 MiB | `422 session_too_large` |

所有响应带 `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset`（秒级 epoch）。

## 5. SSE（hub → daemon）

### 5.1 连接

```http
GET /api/v1/events HTTP/1.1
Accept: text/event-stream
Authorization: Bearer phk_...
Last-Event-ID: 10231            # 重连时可选
Cache-Control: no-cache
```

服务端响应头：

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
Connection: keep-alive
X-Accel-Buffering: no
```

- 每主机最多 **1 条活跃连接**；新连接会顶替旧连接（旧流收到 `event: reset` + `reason: superseded` 后关闭）。
- 连接建立后立即发送 `retry: 3000` 与当前 `serverTime` 注释。

### 5.2 帧格式

```text
retry: 3000

: hub-time 1762700001000

id: 10231
event: deliver
data: {"deliveryId":"dlv_...", ...}

: hb 1762700016000
```

- `data:` 为单行 JSON（不允许多行 data）；
- `id:` 为全局单调事件号（hub `sse_events.id`）；
- 心跳注释 `: hb <ts>` 每 15 s；客户端 45 s 无任何数据视为断线。

### 5.3 事件

**`deliver`**

```jsonc
{
  "deliveryId": "dlv_...",
  "agentId": "a_...",
  "nativeSessionId": "019a...",

```

**`import`**

```jsonc
{

```

**`export_native`**（同 kind 导入的原生快照）

```jsonc
{
  "exportId": "exp_...",
  "transferId": "trf_...",
  "agentId": "a_...",
  "nativeSessionId": "019a...",
  "format": "pi-jsonl-v3",
  "expiresAt": 1762703600000
}
```

**`reset`**

```jsonc
{ "reason": "buffer_expired", "sinceEventId": 10000 }
```

原因：`buffer_expired`（重放缓冲已过期）/ `superseded`（被新连接顶替）/ `server_restart`。
客户端收到后 MUST：`GET /api/v1/deliveries?state=pending` + `imports` + `exports` 补齐，
并记录新的 `Last-Event-ID`（从下一事件继续）。

### 5.4 重放与 Last-Event-ID

- hub 为每个 host 保留最近 **1000 条事件或 1 小时**（先到为准）；
- 重连带 `Last-Event-ID: N` → 重放 `id > N` 的事件；
- 若 `N` 小于缓冲下界 → 发送 `reset`（`buffer_expired`），随后从当前时刻继续；
- 事件 id 单调递增；重放顺序与原始顺序一致；
- 客户端 MUST 以**业务 id**（deliveryId/importId）做二次幂等。

### 5.5 ack 与 result

**ack**（daemon 开始执行时）

```http
POST /api/v1/deliveries/{deliveryId}/ack
{ "acceptedAt": 1762700001000 }
```

**result**（终态）

```jsonc
// 成功
{ "ok": true,
  "result": { "state": "completed", "nativeMessageId": "msg_...",
              "settledAt": 1762700030000, "warnings": [] } }

// 失败
{ "ok": false,
  "error": { "code": "conflict", "message": "session modified at 1762700002000",
             "retryable": false } }
```

- ack 超时（60 s）未收到 → hub 重投（`attempt++`，最多 5 次）；
- result 超时（默认 10 min）→ `expired`，不再重投；
- 同一 `deliveryId` 重复 result → 幂等返回；
- `state` 允许 `completed` / `failed`（`accepted/running` 由 ack 或后续可选进度事件表达）。

**export_native 结果**

```http
POST /api/v1/exports/{exportId}/result
{ "ok": true, "result": { "nativeRef": "upload:upl_...", "sha256": "hex", "bytes": 102400 } }
```

- 源 daemon 先 `POST /api/v1/uploads`（kind=`native-snapshot`）→ PUT 文件 → 再回 `nativeRef`；
- hub 把 `nativeRef` 放进 import bundle 的 `native.blobRef`；
- 目标导入完成或 TTL（1 h）后删除临时 blob；
- 仅同 kind、仅 admin 发起；结果幂等（同 exportId）。

**pending 补齐**

```http
GET /api/v1/deliveries?state=pending&limit=100
GET /api/v1/imports?state=pending&limit=100
GET /api/v1/exports?state=pending&limit=100
```

返回与 SSE 事件同构的数组（含 `attempt`/`expiresAt`），供断线/`reset` 后恢复：

```jsonc
{ "items": [ { "deliveryId": "dlv_...", "agentId": "a_...", "nativeSessionId": "019a...",
               "hubSessionId": "hs_...", "message": "...", "policy": "idle-only",
               "attempt": 2, "expiresAt": 1762700600000 } ], "nextCursor": null }
```

图片在事件里只给 `url`（hub 侧短期签名/鉴权），避免 SSE 大包；小图（≤ 64 KiB）MAY 内联 `dataBase64`。
图片下载：`GET /api/v1/deliveries/{deliveryId}/images/{index}`（Bearer，URL 短期有效）。

### 5.6 命令幂等与并发

- 同 `deliveryId`：daemon 执行前查本地已完成表（建议保留 7 天），已完成则直接回 result；
- 同 `importId`：同上；
- 同 `exportId`：同上；
- 同一 native session 的 `deliver`/`import` MUST 串行；不同 session MAY 并发（daemon 自行限制）。

### 5.7 SSE 客户端要求

- 断线指数退避（1s→60s，带抖动），期间仍用 REST pending 补齐；
- 必须保存最后 `id` 到磁盘，重启后带 `Last-Event-ID`；
- 必须处理 `reset`，不得假定事件不丢；
- 不得把 SSE 用于回执（回执一律 REST）。

## 6. Bundle（导入）

### 6.1 bundle 内容

格式见 000 §10.3（`hub-session-bundle/1`）。`bundleUrl` 指向：

```http
GET /api/v1/bundles/{ref}
Authorization: Bearer phk_...
Range: bytes=0-1048575
```

- 响应 `application/gzip` 或 `application/json`（按 bundle 内部编码），带 `ETag`、`Content-Length`、`Digest`；
- 支持 `Range`（大包分块）；不支持时返回 `200` 全量；
- `native.blobRef` 指向临时原生存档（仅同 kind）；下载后校验 sha256；
- 下载完成 MUST 校验 `bundleSha256`（与 SSE 事件一致）；
- `ref` 有效期默认 1 h，过期 `410 bundle_expired`。

### 6.2 导入结果

```http
POST /api/v1/imports/{importId}/result
{
  "ok": true,
  "result": {
    "nativeId": "019c...",
    "nativePath": "C:\\work\\...\\<ts>_<id>.jsonl",
    "warnings": ["provider/model 元数据未迁移"]
  }
}
```

失败同 §5.5 的 error 结构（`unsupported` / `cwd_not_allowed` / `invalid_bundle` / `conflict` / `io`）。

## 9. 限流、重试与超时

| 操作 | 超时 | 重试 |
|---|---|---|
| `GET /meta` | 10 s | 3 次 |
| `manifest` | 30 s | 3 次（退避 1/2/4 s） |
| `sync/sessions`（内联） | 120 s | 3 次（同 `Idempotency-Key`） |
| upload PUT | 30 min | 3 次（Range/重传） |
| SSE 连接 | 长连接 | 指数退避重连 |
| deliver（daemon 执行） | 10 min | 由 hub 重投（最多 5 次） |
| import（daemon 执行） | 30 min | 2 次 |

- 所有重试 MUST 带原 `Idempotency-Key`（若有）；
- `Retry-After` 优先于本地退避。

## 10. 版本与兼容

- URL `/v1`；响应头 `X-Hub-Api-Version: 1`。
- 同版本内新增字段必须可选；客户端 MUST 忽略未知字段。
- 删除/改名字段 → `/v2`。
- `minDaemonVersion` 由 hub 配置；低于该版本 → `426`。
- canonical entry 的 `version` 固定为 3（pi v3）；未来 pi v4 发布时新增 `canonicalVersion` 字段协商。

---

## 11. 安全要求

- 全链路 TLS；daemon 校验证书（可 pin）。
- 令牌来自 hub-service 配置（建议只存哈希）；可按 daemon 单独更换。
- 服务端 MUST 校验 token ↔ hostId 绑定，忽略 body 中的 hostId。
- 服务端 MUST 限制请求体/解压后大小、JSON 深度、单行大小。
- 日志 MUST NOT 记录 token、message 正文、entry 原文。
- console Cookie：`HttpOnly`、`Secure`、`SameSite=Lax`；写接口 CSRF + Origin 校验。
- 导入路径必须在 daemon 的 `allowedRoots` 内；hub 不信任 `nativePath`。

## 12. 一致性与测试

- 提供 **JSON Schema**（`protocol/schema/*.json`）与固定样例（`protocol/fixtures/*.json`）。
- 契约测试 MUST 覆盖：
  1. manifest 的 `new/ok/skipped/full/quota`；
  2. delta 的边界（`> since`、同毫秒、重复 entryId、内容冲突）；
  3. full 的原子替换与幂等；
  4. upload 的流式校验、sha256、过期；
  5. SSE 重连/`Last-Event-ID`/`reset`/重复事件；
  6. ack/result 的幂等与超时重投；
  7. 错误码与 HTTP 状态映射；
  8. 限流头与 `Retry-After`。
- 参考实现：TypeScript（hub）与 Rust（daemon/插件）各一份 schema 解析与校验。
